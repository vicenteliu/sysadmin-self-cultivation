# 我怎么用 AI 学习和运维

> 元层。每个平台模块都有自己的 AI-ramp；这一篇是它们背后共享的那套哲学 —— 以及那个不让
> AI 悄悄搞砸事情的部分。

这整个项目的主张是：在 2026 年，一个系统管理员的优势不在于懂每一个服务 —— 而在于
**判断力，加上一条 AI 增强的 ramp**。而那只有在 AI 被有纪律地使用时才成立。两条规则做掉了
大部分的活：

## 规则 1 —— AI 管速度，判断力管真伪

AI 在那些*繁琐但不难*的部分上极其出色：把一个你已经拥有的概念翻译进一个新平台的词汇、起草
那条 IAM policy、写出第一版 Terraform、解释一个报错。它在那些*承重*的部分上并不可靠：确切
的 API 参数、当前的默认值、安全关键的配置、成本。所以分工是固定的：

- **AI 起草。** 你在几分钟而不是几天之内拿到一个能跑的第一版。
- **你验证。** 每一个服务名、参数和权限都要对着官方文档核过，而每一次变更在被信任之前，都要
  在一个带硬性预算告警的一次性沙箱里跑过。

要针对着设计的那个故障模式是**自信的错误** —— 一个听起来说得通、却在微妙处、昂贵处或危险处
偏掉的答案。假设草稿有大约 90% 是对的，而你的活是猎那 10%。

## 规则 2 —— 把一切锚定到你已经会的东西上

最快的学习 prompt 不是"教我 X"。而是*"我已经理解 \<Linux / 网络 / IAM / 我真正会的随便什么\>
—— 把 X 映射到那上面；给我差值。"* 这完全跳过了新手税，也打在一个有经验的 admin 真正的强项
上：概念本来就在，新的只有标签。

## 可复用的 prompt 套件

- **翻译器** —— "假设我懂 \<某个基础\>，解释 X；只给差值。"
- **80/20** —— "X 里面一个 admin 每天用到的那 20% 是什么；哪些我可以先放着？"
- **坑猎手** —— "X 上最常坏的三件事，以及怎么避开它们。"
- **最小权限生成器** —— "恰好能做到这件事、不多一分的最紧 policy/role。"（然后手工再收紧。）
- **评审员** —— "审一遍这份 IaC / policy / 设计的安全、成本、可靠性风险。"
- **小黄鸭** —— 贴一个报错 / CLI 输出 / 被拒绝的请求；"这是什么意思，我该怎么调试？"

## AI **不**替代什么

它不会感觉到一条 security group 离暴露一个数据库只差一行。它不会在凌晨三点扛下那次事故。
它无法承担责任。这门手艺 —— 那份最小权限的直觉、"这个为什么够不到那个"、读懂一次故障、
在成本与可靠性之间权衡 —— 仍然是你的。AI 只是把"**拥有**那份判断力"和"把它**施加**到一个
你从没碰过的平台上"之间那几个月的死记硬背查找，给拿掉了。

那就是自我修养：持续磨那份判断力，让机器去扛查找。
