# 一个 MDM 管什么，以及它管不了什么

> 🌐 **语言：** [English（默认）](../../../endpoint/management.md) · **中文**
>
> ⚠️ 本项目**默认语言为英文**，`endpoint/management.md` 是"事实来源"。本页中文是多语言支持的一部分，可能略滞后于英文版；两者不一致时以英文为准。

> [`provisioning.md`](provisioning.md) 把机器送到了某个人手上。这篇笔记是另一半：
> **在那个人用了它十八个月之后，它怎么还处在一个你描述得出来的状态。** [README](README.md) 画出
> 那条纳管—配置—合规—行动的循环；这里是它底下那份设计，以及那些这条循环悄悄敞着口的地方。

**立足点，先说在前面，因为它在这篇笔记里面会变。** 🔨 用于那个模型，以及它的两种方言 ——
**Jamf** 和 **Workspace ONE / UEM** 在一片机队上亲手运维过，其中在 Jamf 那一侧还拥有过一个地区的
测试与维护。🧭 用于 **Intune、Autopilot 和 ConfigMgr** —— 同一门纪律，经由一个这位作者测绘过而不是
跑过的控制台 —— 以及 🧭 用于**深度的 iOS 与 Android 机队合规 profile 工程**，在那里纳管和生命周期
是 🔨，而机队 profile 的精通是那条 ramp。[README](README.md) 从它被写下来起就这么说了；在这里
重复一遍，是因为一位直接抵达这一页的读者否则看不到它。

## 你是在租一个管理面

关于这一层最有用的那一件事：**一个 MDM 只能管理那个操作系统厂商决定暴露出来的东西。** 它不是一个
拥有那台机器的通用 agent。它是一个协议的客户端，而那个协议的面由别人控制，而控制它的是谁，逐平台
不同。

那有三个决定了多数设计的后果：

- **那个面按厂商的日程变，不按你的。** payload 会被加上、被废弃，偶尔被拿走。某样你依赖的东西，
  可能在你的估算面什么都没做的情况下变成不被支持。
- **"MDM 能不能做 X"是一个关于 OS 的问题，不是一个关于 MDM 的问题。** 两个产品会在人机工程、
  报表和规模上不同；它们很少在"某个设置可不可管"上不同。当它们不同时，通常是因为一个已经发布了
  对某个 payload 的支持而另一个还没有。
- **因此在产品之间的选择不是一次能力对比。** 它是一个关于它们周围那片估算面的问题，也就是下面
  那一节。

**这也是为什么这个仓库里那些厂商名是签名而不是推荐**
（[ADR-0002](../docs/adr/0002-the-reference-office-is-parameters-not-a-bill-of-materials.md)）。
可迁移的知识是那个协议和那门纪律；那个控制台是一种你两周就学会的方言。

## 已纳管、被管理着、合规，是三句不同的声称

它们在状态会上被混着用，而它们不是一回事，而它们之间那些缝正是估算面腐烂的地方。

| 声称 | 它意味着什么 | 它怎么失败 |
|---|---|---|
| **已纳管** | 这台设备有一个管理身份和一段信任关系 | 那是一次性事件；一台设备可以被纳管过，然后再也不签到 |
| **被管理着** | MDM 当前持有一段活的关系，并且能对它动手 | 这台设备关机了、不在网上，或者静默地丢掉了它的纳管 |
| **合规** | 这台设备当前满足你写的那条策略 | 这里没有任何东西说有人**对它做过**任何事 |

**危险的是第三个。** 一条只报告、不动手的合规策略是一块仪表盘。这个仓库对此有一句话，是在另一个
lab 里挣来的：*一个检查凭它排除了什么赢得位置，不是凭它报告了什么*
（[`remote-access-four-causes`](../../../cross-cutting/labs/remote-access-four-causes/)）。它在
终端上的版本是：**一台不合规、而没有挂上任何动作的设备，是一台你记录了而不是修好了的设备**，
而那份记录让它看起来像是被处理了。

因此那个设计问题不是*这条策略该检查什么*。而是**当它失败时会自动发生什么，以及这台设备被允许
失败多久。** 这两个都需要在策略被写下来之前有一个答案。

## 那个范围问题有一根时间轴

这是真正困难、而且很少被说出来的那一部分。

你把一条策略的范围定到一个组上。那个组由目录填充。那个目录由入转离维护。在
[参考办公室](../the-reference-office.md#parameters)里那是**一年大约四十个事件**，外加那些根本没有
任何东西去触发的内部调动。

所以：**一条策略所适用的那批机器，会在没有任何人编辑这条策略的情况下改变。** 你在写它那天复审过
那个爆炸半径。那个爆炸半径是一个移动的量，而没有人再复审它。

那是那个转岗问题（[`build-out/15`](../build-out/15-joiner-mover-leaver.md)）的终端形态，而它和
[`permission-sprawl`](../../../cross-cutting/labs/permission-sprawl/) 里那条发现是同一个形状：
一条在被做出那天完全正确的授予，对着一群在它底下周转掉的人。

**该拿它怎么办，按成本从低到高：**

1. **在编写时把那个爆炸半径写下来** —— 那个数目，以及这条策略做的最糟的事。这是免费的，而几乎
   没有人做。
2. 凡是这条策略关乎设备而不是关乎人的地方，就**按合规状态或设备属性、而不是按人形的组来定范围**。
   把设备形状的策略定范围到人形的组上，正是一台躺在抽屉里的笔记本收到一次配置变更的方式。
3. **按一个节奏重新推导那个数目**，并在它移动超过你预期时告警。一条目标集合这个季度长了四成的
   策略，在告诉你一件关于那个目录的事，不是关于这条策略的事。

## 你在一片 Apple 估算面里会发现什么，以及它说明什么

当作**签名**来读 —— 一样东西的存在告诉你关于你走进的这个组织什么 —— 而不是当作一份购物清单。
那个区分在这里是一条规则，不是一句免责声明：点一个产品的名去帮某人认出他在哪儿，是可迁移的；
点一个产品的名去告诉他该买什么，是会过期的。

**不管你还发现什么，这两样都不是可选的：**

- **一个设备注册渠道** —— 厂商侧那份说"这些序列号属于这个组织"的记录。没有它就没有自动化纳管、
  也没有 supervision，而这片估算面就是在做 [`provisioning.md`](provisioning.md) 的第一栏 ——
  不管它是不是有意的。
- **Supervision。** 纳管说的是这台设备被管理着。**Supervision 说的是这个组织拥有它**，而它解锁
  一个实质上不同的策略面。一片机队已纳管、但没有 supervision 的 Apple 估算面，通常是从一段 BYOD
  的过去长出来的，而那段历史解释了它身上大部分看起来奇怪的地方。

**那个管理产品本身说明什么：**

| 你发现什么 | 它通常意味着什么 |
|---|---|
| 一个 **macOS 专精平台** | Apple 在这里是一等平台，不是被容忍的那个。可以预期很深的策略覆盖、一个脚本层，以及一个熟悉 Apple 发布日历的团队。往往是一支设计、工程或研究人群的标志 |
| 一个**多 OS 的 UEM** | 有人判定"三个都在一个控制台里"比在任何一个上做深更要紧。通常是一片有中央终端团队的大估算面，而且通常是一个所有人都心知肚明的折中 |
| 那个**微软估算面的默认项** | 身份和生产力已经是微软的，而终端跟了上去。它对 Apple 的支持是真实的、也在改进，而那很少是当初做这个选择的原因 |
| 一个 **Apple-only 的较新入场者** | 一个更年轻的组织，从 Apple 起步，从来没有一片 Windows 估算面要去统一 |
| 上面**两个同时在跑** | 一次停滞的迁移，或者一次收购。在提议任何东西之前先搞清楚是哪一个 |

**那份判断，平白地说：** 这个选择是由终端周围那片估算面决定的 —— 哪个目录、哪套办公套件、几个
操作系统，以及 Apple 是多数还是少数 —— 而几乎从来不是由某个别家没有的能力决定的。一次产出了一张
功能矩阵的评估，通常问错了问题。

## 一个 MDM 做不了什么

值得说出来，因为那张循环图暗示的比它交付的多：

- **它管不了一台不签到的设备。** 仪表盘上每一个数字都是一句关于那些报了数的机器的陈述。有意思的
  那些机器是没报数的那些。
- **它没法让一条策略对一台从没被纳管过的设备追溯生效。** 你管得了的那片估算面和实际存在的那片是
  两个不同的集合，而那个差别又是[清册](../CONTEXT.md)对着资产台账。
- **它决定不了谁应该拥有什么。** 它施行一个在别处做出的决定，而这也是为什么在其他每一种自动化都
  建好之后，访问与权限仍然是最大的那个工单类别
  （[参考办公室](../the-reference-office.md#parameters)）。
- **它替代不了那份托管设计。** 强制加密是一个设置。那把恢复密钥会怎么样，是一个完全不同的问题，
  而它是 [`encryption-and-keys.md`](encryption-and-keys.md)。

## 诚实边界

🔨 **那个模型，以及它的两种方言。** Jamf 和 Workspace ONE / UEM 在一片真实机队上亲手运维过 ——
纳管、配置 profile、合规策略、定向应用分发，以及在 Jamf 那一侧对测试与维护的地区所有权。
"已纳管对被管理着对合规"那个区分和"范围随时间移动"那个问题，两个都是运维疤痕组织。

🧭 **Intune、Autopilot 和 ConfigMgr** —— 测绘过、ramp 过、验证过，没有跑过。
🧭 **深度的 iOS 与 Android 机队合规 profile 工程** —— 纳管和生命周期是 🔨；机队 profile 的精通是
那条 ramp。

**未作声称：** 授权经济学、厂商合同谈判，以及任何一句关于一个组织该买哪个产品的陈述。
