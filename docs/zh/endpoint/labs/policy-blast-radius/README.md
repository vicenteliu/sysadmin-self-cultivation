# Lab —— 控制台说 3，策略覆盖 22，而三年之后它覆盖 30

> 🌐 **语言：** [English（默认）](../../../../../endpoint/labs/policy-blast-radius/README.md) · **中文**

> **输入：** 无 · **输出：** 一份逐步骤的报告，讲这条策略当时和现在到底覆盖到什么 ·
> **风险：** 无 —— 不用 MDM、不用租户、不用设备、不用凭据 · **root：** 不需要

**目标：** 回答 [`endpoint/management.md`](../../management.md) 说在任何策略发布之前都该回答的
那个问题 —— *这条策略覆盖多少台设备，以及它对它们做的最糟的事情是什么* —— 然后指出：这个答案有一个
没人给它挂上的有效期。

**你会练到：** 去*解算*一个范围而不是*读*一个范围，以及那个把你已经签过字的数字重新推导一遍的习惯。

## 这个 lab 为什么是纯本地的

范围划定是一个关于集合成员随时间变化的*算术*问题，不是一个厂商问题。每一个管理平台底下都是同一个
形状 —— 一个组、一条嵌套规则、一条排除，以及挂在人身上的设备 —— 所以它完全可以用一个模型表达出来。

[这个 lab 所取代的那份规格](../../README.md)要求一个试用 MDM 和一台备用设备。那是一次**引导式走
查**，不是一个 lab（[`CONTEXT.md`](../../../CONTEXT.md) 把这两个词分得很开），而且它教的会是那个
控制台，而不是那个问题 —— 你没法在一个试用租户上看着三年过去。

不用 MDM、不用租户、不用设备、不用凭据、不用 `pip install`。Python 标准库，完全确定性，CI 也跑
得了。

## 跑它

```bash
python3 endpoint/labs/policy-blast-radius/blast_radius_drill.py
python3 endpoint/labs/policy-blast-radius/blast_radius_drill.py --break-it
```

exit code `0` 表示关于这个教训的每一条断言都成立。

## 它建模的那间办公室

不是编出来的 —— 是[参考办公室写明的那些速率](../../../the-reference-office.md#parameters)，
向前跑 1095 天：横跨八个职能的一百个人，一年大约二十三个入职、十七个离职，每人一台设备、三年更新
一次，货架上五台备机。

模型里有一个数字**不是**来自参考办公室，而这个演练在一条注释里说了出来：**内部转岗。** 那个文件
刻意不给出转岗率，因为它推导不出来，也不值得编一个。这个演练要跑起来需要一个，就用了一年十二个，
而这里不是去找那个数字的权威出处的地方。

这条策略的范围指向一个访问包，而它长得像每一个用了十八个月之后的访问包：**一整个职能被嵌套进来，
外加三个被单独加进去的人**，因为某个时候某人需要过一次访问。一个排除组保护着另一个职能。

## 你会看到什么

1. **第一天，控制台上那个数字和真实的数字就不一样。** 屏幕显示 **3** 个直接成员。这条策略覆盖到
   **22** 台已纳管设备。这个缺口不是一个 bug —— 嵌套不会被显示出来，有人在一次更新之后手里握着
   第二台机器，而货架上一台备机不属于任何人、因而不匹配任何排除。

2. **三年之后它覆盖 30 台，而没有人编辑过这条策略。** 一次 **+36%** 的漂移，完全是由入职、离职和
   转岗在一个嵌套组里进进出出造成的。没有任何变更记录可供复审，因为什么都没变过。

3. **那条排除也在漂，而且是往错的方向漂。** 第 0 天有十三个人被豁免，现在有十六个 —— 但其中
   **只有五个是同一批人**。八个人因为换了团队，丢掉了一份没人吊销过的豁免。什么都没被触发，因为
   [一次转岗是一场对话](../../../build-out/15-joiner-mover-leaver.md)，不是一个事件。

4. **有八台已纳管设备根本没有持有人** —— 五台备机和三台没人擦除过的退回机。它们之所以匹配这个
   范围，原因是结构性的而不是粗心：**排除是围绕人写的，而这些设备没有人。**

5. **`--break-it` 用控制台那种方式去数**，而这是值得坐下来好好待一会儿的那部分。它在第 0 天报告
   **3**，在第 1095 天还报告 **3**。这个数字是*稳定的*、是*被自信地显示出来的*，而它从来只对一个
   没人问过的问题是对的。三条断言会挂掉，而第三条才是要紧的那条：**这个方法没法告诉你它的答案已经
   过期了**，因为它根本没有关于时间的任何表示。

## 验证（别光信这个脚本说的）

- **把 `MOVERS_PER_YEAR` 改成 `0`** 再跑一遍。那个漂移会变小，但不会消失 —— 剩下的是纯粹的入职和
  离职，而那就是即便在一间从没有人换团队的办公室里也存在的地板。
- **把 `HORIZON` 设成 `365`**，看看一年（而不是三年）时的漂移。它那时就已经看得见了，而这正是
  "要有一个节奏，而不是一次年度复审"的论据。
- **把 `groups_on()` 里 `restricted-config` 那三个单独授予去掉**再跑。控制台上那个数字变成零，
  而这条策略仍然覆盖着一个职能的大部分 —— 同一个失败的病态版本，也是一片估算面在每个访问包都纯
  由嵌套组搭起来时会走到的地方。
- **往那个货架循环里加一台备机**，确认它落进了覆盖范围里。这个模型里没有任何一条策略语言本来能
  拦住它，而这正是重点。

## 重点

**一个爆炸半径是时间的函数，而它是被当成一个常量来复审的。**

你在写它的时候算过一次，算的依据是一块显示直接成员的屏幕。从那以后，那个数字就住在一份永远不会被
重新打开的变更记录里，而真实的覆盖范围正在被一个[一年周转大约四十次](../../../the-reference-office.md#why-these-numbers)的目录持续地重算着。

那个补救不是一个更好的控制台。它是**按一个节奏把那个数字重新推导一遍，并对那个差值告警** ——
一条目标集合在这个季度长了三分之一的策略，告诉你的是关于那个目录的事，不是关于那条策略的事。

而这个故障有着这个仓库反复找到的那个形状：这里没有任何东西配错了，没有人粗心，每一次单独授予在它
被做出的那一天都是对的，而那项缺失的控制从来就不是一项访问控制。它是一次**重新推导** ——
这也正是 [`transcript-retention`](../../../cross-cutting/labs/transcript-retention/) 关于过期期限
所得出的同一个答案，只是从另一头走到的。
