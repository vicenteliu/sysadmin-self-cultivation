# 横跨三个操作系统的发放

> 🌐 **语言：** [English（默认）](../../../endpoint/provisioning.md) · **中文**
>
> ⚠️ 本项目**默认语言为英文**，`endpoint/provisioning.md` 是"事实来源"。本页中文是多语言支持的一部分，可能略滞后于英文版；两者不一致时以英文为准。

> [README](README.md) 说的是*终端这门纪律是什么*。这篇笔记是它点了名却没有回答的那个设计问题：
> **当一套发放平台必须同时覆盖 Windows、macOS 和 Linux 时，它决定什么？**
> 写自设计并运行过一套被全组织采用、累计发放了六位数台设备的平台 —— 而这也正是为什么这篇笔记里
> 诚实的那些部分讲的是什么**没有**迁移过来。

## 那个问题底下的那个问题

*我怎么发放三个操作系统*，几乎总是两个问题穿着一件外套。

**一个是交付问题**：一台机器怎么从一个箱子到达一个人的桌上，并且处在他能干活的状态。
**另一个是状态问题**：在那个人用了它十八个月之后，那台机器怎么还处在一个你描述得出来的状态。

它们由不同的系统、按不同的节奏来回答，而把它们搞混是这一层上最常见的结构性错误。这篇笔记讲的是
第一个。[`management.md`](management.md) 讲的是第二个。

## 那两个时代，以及知道你在哪一个里

今天在役的发放模型恰好有两个，而那个问题不是哪个更好 —— 而是**你的估算面实际在哪一个里**，
因为多数估算面两个都在，而且没有注意到。

| | 你来造那台机器 | 厂商来造那台机器 |
|---|---|---|
| **它怎么开始** | 网络启动，一个你做的镜像，由你来施加 | 一个在出货前就被注册到你组织名下的序列号 |
| **你维护什么** | 每一代硬件一个黄金镜像，外加驱动 | 一份纳管 profile 和一套策略 |
| **OS 从哪来** | 你的镜像 | 基本是 OS 厂商的 |
| **什么会弄坏它** | 一款网卡驱动不在镜像里的笔记本型号 | 一台从没被注册过、或者被注册到错误租户下的设备 |
| **你在哪儿碰那台机器** | 一张工作台、一位技术员、三十到六十分钟 | 哪儿都不碰 —— 一个快递员和用户自己的手 |

**决定你在哪一个里的那些判据**，而没有一条是偏好：

- **厂商能在采购时把硬件注册到你名下吗？** 如果你走的采购渠道支持它，第二栏就是可用的。如果你买
  的是翻新机、或者在一个没有那个渠道的地区、或者那些机器已经在柜子里了，那就不可用 —— 而再多的
  策略设计也改变不了这一点。
- **这个 OS 到底有没有一条首次开机的纳管路径？** 三个里有两个有，而且很干净。第三个才是有意思的
  那个，它在下面有自己的一节。
- **你控不控制那台机器第一次接触的那个网络？** 网络启动需要一个你拥有的网络、在一个房间里、
  而机器插在上面。厂商纳管需要的是任意一条互联网连接，以及根本不需要房间 —— 而这正是在办公室
  不再是人们所在之处以后，这个模型赢下来的全部原因。
- **这片估算面里有多少个硬件型号？** 这才是真正决定它的那一条，也是再下一节的主题。

**参考办公室在第二栏里，而且它这么说了。**
[`build-out/04`](../build-out/04-devices-and-images.md) 把镜像放在 OS 厂商那儿，把技术员放在
零分钟上。对一百个人、通过正常渠道买当代硬件来说，那是正确答案。它不是处处的答案，而一篇只描述
它的笔记，描述的会是那个容易的情况。

## 这三个操作系统实际共享什么

比一张组织架构图所假定的更少，而这份诚实的核算要紧，因为它决定你需要多少人。

**它们共享那个形状**：一台设备获得一个身份、收到一份对它预期状态的描述，然后向它收敛。那是真的，
而且那正是为什么一个团队能把三个都跑起来。它同时也是它们所共享的全部。

**它们不共享那套机制**，而每一个都在一个不同的方向上有主张：

- **macOS** 拥有三者中最严格也最干净的纳管故事，因为那个 OS 厂商同时运营着设备注册渠道和管理
  协议。那份干净的代价是**你做不了任何这个协议不提供的事情**。那份工作是知道那条边界，不是绕过
  它。
- **Windows** 同时承载着两个时代，而这正是为什么 Windows 估算面是那种有两套发放系统并行运行、
  而没人能把任何一套下线的估算面。它的镜像血统很深、工具很齐，也正是上面第一栏在多数大型估算面
  里仍然存在的原因。
- **Linux** 基本没有一个消费级的首次开机纳管故事，所以它默认留在第一栏 —— 而且因为它从上到下都
  可脚本化，它往往被那套跑服务器的同一批配置管理工具发放。那是一个合理的答案，而它有一个人们会
  漏掉的后果：**那些 Linux 终端最后是被一个和另外两个不同的团队管的。**

**最后那一点才是那条真正的发现。** 问一个组织它跑几套终端管理平台，它会说两套。数一数是三套，
因为那些 Linux 笔记本是被跑 Ansible 的那个人在处理。这片估算面不是错的 —— 它是无人记账的，
而那是另一个问题，也是更糟的一个。

## 硬件多样性才是那个把它弄坏的东西

README 把这个叫作*云永远不会给你看的那个漏水点*，而在规模之下它不是一个漏水点，它是那条设计约束。

**一个镜像、十二款笔记本型号，而其中一款不接受那个 wifi 驱动。** 那一句话就是发放服务器和发放
终端之间的全部差别。一片服务器机队是成批买的，按采购政策就是同质的。一片终端机队是累积出来的：
一条型号线的三个代际、供应短缺期间买的一批、设计团队那些机器、某次收购里继承来的那些机器。

**它所逼出的那些决定，按搞错的代价从高到低排：**

1. **支持多少个硬件型号，以及例外流程是什么。** 这是一个看起来像采购问题的**政策**问题。
   [`build-out/04`](../build-out/04-devices-and-images.md) 要的正是这个，而它是那一步里杠杆最高的
   一句话。每一个型号都是一套驱动、一列测试矩阵，以及一份反复出现的成本 —— 而不管有没有人把它
   写下来，那份成本都由那套镜像平台来付。
2. **那个镜像是通用的还是逐代的。** 一个通用镜像加驱动注入能走得更远，也会以更晦涩的方式失败。
   一个逐代镜像很简单，而且会倍增。
3. **谁拥有那套测试矩阵，以及它什么时候跑。** 那个故障模式不是某个型号坏了。而是某个型号
   *在你已经推给所有人的那个镜像里*坏了。
4. **那个死活不合规的型号怎么办。** 总会有一个。诚实的答案是一份带归属人和复审日期的、写下来的
   例外，不是一个没人写下来的绕行办法 —— 而这和 [`build-out/08`](../build-out/08-endpoint-security-and-patching.md)
   在打补丁上所要求的是同一门纪律，出于同一个理由。

**厂商纳管不移除这个问题，它挪动这个问题。** 你不再维护驱动，而开始维护"每一台机器都被正确注册
过"这个假设。那个假设会静默失败，在卸货口，而你会在某个人的第一个早上发现它。

## 规模改变什么，以及不改变什么

在六位数台设备上跑这件事和在一百台上跑，是两份不同的工作，而那个差别不是人们以为的那个。

**变的：**

- **一切都变成一个队列。** 在一百台设备上，发放是一个事件。在十万台上它是一个速率，带着一个积压、
  一个吞吐，以及一个会移动的瓶颈。那个瓶颈几乎从来不是镜像。
- **例外率不再是噪声。** 一百台的百分之二是一个技术员处理的两台机器。十万台的百分之二是一个团队。
- **地区现实到来了。** 不同的渠道、不同的硬件可得性、不同的网络条件、不同的假期。一个假定了一个
  站点的平台，会发现自己把那个假定编码在了十几个地方。
- **回滚变成你真正需要的那个功能。** 在小规模上你往前修。在大规模上，一个坏镜像会在任何人报障
  之前抵达数千台机器。

**不变的** —— 而这是可迁移的那一半：

- **那个爆炸半径问题。** 在任何策略或镜像发出去之前：*这会够到多少台设备，以及它对它们做的最糟
  的事情是什么？* 那个问题在一百台和十万台上是一模一样的。只有跳过它的后果会随规模变大。
- **staging 不是可选的，而且它总是那个被砍掉的东西。** 一圈你自己的机器，然后一个友好的团队，
  然后一个地区，然后所有人。每一片跳过它的估算面，都有一个关于它现在为什么不跳的故事。
- **另一端那个人。** 这条流水线的产出，是一台一个非技术人类在他第一天要用的机器。那就是那项验收
  测试，而它不会因为量大而变容易。

## 具体到参考办公室

一百个人，[一年大约二十三个入职和三十八次换代替换](../the-reference-office.md#parameters) ——
所以**一年大约有六十二台机器易手，而其中不到四成是因为有人入职。**

那个比例是多数发放平台从来没被给过的那个设计输入。一条围着入职建起来的流水线，把少数情况处理得
很好，而把多数情况用手处理。那条换代路径 —— 一个已经有一台能用的机器、已经有一个账号，而需要他的
新机器与旧的无从分辨的人 —— 才是实际量所在的地方，而它有一项入职没有的要求：
**那台旧机器必须回来、被抹掉，并且诚实地离开那份台账**，而那正是
[`asset-reconciliation`](../../../cross-cutting/labs/asset-reconciliation/) 的全部主题。

## 诚实边界

🔨 **亲手做过，而这是它的深水区。** 设计并运行过一套被全组织采用的多 OS PXE 与镜像式发放平台，
累计发放六位数台设备；应用打包与定向分发；在量级上做镜像、给退回机器重装镜像、以及在规模上登记
全盘加密的那份仓库现实。上面那些硬件多样性的材料不是读来的，是疤痕组织。

🧭 **那条 ramp 在哪，而且很具体。** 尤其是 **Autopilot 和 ConfigMgr** —— 用微软的方式做第二栏，
是一个这位作者测绘过而不是跑过的控制台，而 [README](README.md) 一直是这么说的。厂商纳管那个
**形状**通过 Apple 的渠道是 🔨；它的 Windows 方言是那条 ramp。

**完全未作声称：** 采购渠道谈判，以及硬件供应侧的任何东西 —— 除了"它约束那个镜像"这个事实之外。
