# 那架调试梯子，一次一级

> 🌐 **语言：** [English（默认）](../../../cross-cutting/debug-ladder.md) · **中文**
>
> ⚠️ 本项目**默认语言为英文**，`cross-cutting/debug-ladder.md` 是"事实来源"。本页中文是多语言支持的一部分，可能略滞后于英文版；两者不一致时以英文为准。

---

> [`the-stack/02`](../the-stack/02-network.md) 画出了那架梯子：这个名字解不解析得出来、有没有
> 路由、过滤放不放行、大包会不会卡，然后、也只有到那时，你才可以去看。这篇笔记给**每一级配上
> 那条验证它的命令** —— 而且更要紧的，说清**一个通过的回答让你可以停止考虑什么。**
> 记录在 [`docs/questions/networking.md`](../docs/questions/networking.md)。

**为什么这刻意不是一份命令参考。** 一份参考按工具组织，回答*这条命令干什么*。这一篇按**问题**
组织，而且每一条都得像这个仓库里每一个检查那样挣得它的位置 ——
[一个检查凭它排除了什么赢得位置，不是凭它报告了什么](labs/remote-access-four-causes)。
一条什么都排除不掉的命令不是一级，不管它多有名。

梯子是那个不变量。**命令是一种方言**，它们随操作系统、随平台而变；这也是下面每一级的表都很短、
而且没有一张是穷举的原因。

## 第 0 级 —— "它"到底是什么？

在第一级之前，浪费一小时最常见的那种方式：**把梯子爬在错的目标上。** 用户说*那个站点挂了*；
那个站点有四个名字，其中两个是别名，还有一个在楼里解析出来的结果不一样。

问清三件事，并写在工单看得见的地方：**准确的那个名字或地址**、**从哪台机器**，以及**"好了"应该
是什么样。** 如果第三条你说不出来，那你不是在排障，你是在共情。

## 第 1 级 —— 这个名字解不解析得出来，解析成的是不是你以为的那个？

**那个问题。** 不是*DNS 活着吗*。而是**这个名字**，从**这台机器**上，解不解析成你相信的那个
地址。

| 在哪 | 那条命令 | 它回答什么 |
|---|---|---|
| Linux / macOS | `dig +short NAME`，然后 `dig +short NAME @RESOLVER` | 系统怎么回答，然后一个**指名的** resolver 怎么回答 |
| Windows | `Resolve-DnsName NAME` 和 `Resolve-DnsName NAME -Server RESOLVER` | 同样那两个问题 |
| 到处 | Linux 上的 `getent hosts NAME` | **resolver 库**返回什么，而它不总是 `dig` 返回的那个 |

**一次通过排除掉什么：** 整个 DNS，**对你刚跑的那个工具而言**。

**而那个附加条件就是那个陷阱。** `dig` 跟你配置里的那个 resolver 说话。一个应用可能用另一个 ——
一个容器的、一个 VPN 客户端的、一个运行时自己的 stub、一个浏览器的加密 resolver。
**一次通过的 `dig` 加上一个失败的应用，是一个 DNS 回答，不是一次 DNS 通过**，而它是这架梯子上
最常见的那个假顶。[远程访问那篇笔记](vpn-and-remote-access.md)是同一个失败，从隧道那一侧看。

**把双 resolver 那个形式当成反射来跑。** 一次查询说的是你拿到了什么；两次说的是*resolver 是不是
那个变量*，而那才是真正的问题，代价是多一行。

## 第 2 级 —— 有没有路由，回程路径在不在？

**那个问题。** 包有没有一条路过去**并且回来**。你通常只看得见前一半，这也是不对称能活这么久的
原因。

| 在哪 | 那条命令 | 它回答什么 |
|---|---|---|
| Linux | `ip route get ADDRESS` | **这个包**会走的那条准确路由，源地址也在内 —— 不是整张表 |
| macOS | `route -n get ADDRESS` | 同上 |
| Windows | `Find-NetRoute -RemoteIPAddress ADDRESS` | 同上 |
| 云上 | 那个子网的平台**路由表**，以及那条对等连接自己的 | guest OS 看不见的那一半 |

**为什么是 `ip route get` 而不是 `ip route show`：** 表告诉你存在什么；`get` 告诉你**会被选中
什么**，而那才是那个问题，并且它施加的是那条马上就要让你意外的最长前缀匹配逻辑。

**一次通过排除掉什么：** 你这一侧的路由。**它排除不掉回程路径**，而且从这里永远排除不掉。当这
一级上的一切看起来都对、连接却还在挂着的时候，不对称是第一个该怀疑的、也是最后一个有人去查的。

## 第 3 级 —— 过滤放不放行，两层都要，两个方向都要？

**那个问题。** 是不是有什么东西在丢它 —— 而这一级承载着**网络调试里信息量最高的那个单一回答。**

| 在哪 | 那条命令 | 它回答什么 |
|---|---|---|
| 到处 | `nc -vz HOST PORT` | 拒绝、超时，还是开着 —— 下面那个区分 |
| Linux / macOS | `curl -sS --max-time 5 -o /dev/null -w '%{http_code}\n' URL` | 同一个区分，外加那个服务有没有回答 |
| Windows | `Test-NetConnection HOST -Port PORT` | 同上 |
| 云上 | 那个安全组**以及**它底下那个无状态层 | 人们一直忘、直到一个回程包被丢掉才想起来的那一层 |

**那两个回答，以及这个差别为什么比这一页其余部分都值钱：**

- **拒绝**意味着你的包**到了**，而对面有东西主动说了不。路由是通的。到那台主机的过滤是通的。
  问题在远端 —— 一个没在监听、或者绑错了网卡的服务。**你用一个词排除掉了三级。**
- **超时**意味着**你什么都不知道**。它就是一个被丢掉的包、一条黑洞式过滤、一条错的路由和一台
  死掉的主机看起来的样子。一次超时是梯子在告诉你接着往上爬，不是一个答案。

**无状态层就是回程路径死掉的地方。** 一个放行了出站的有状态过滤器记得那条流；一个无状态的必须被
单独告知那个回复，而从客户端看，这个失败长得和一个路由问题一模一样。

**一次通过排除掉什么：** **你所测试的那个方向上**的过滤。和第 2 级同样的不对称附加条件，以及
同样的、它之所以存活的原因。

## 第 4 级 —— 小包能过而大包会卡吗？

**那个问题。** 这条路径能不能承载一个满尺寸的包。它的特征你见过一次就再也认得出来：
**握手完成了，传输卡住了。** 登录成功，下载不动。这是人们会跳过、然后在它下面耗掉一天的那一级。

| 在哪 | 那条命令 | 它回答什么 |
|---|---|---|
| Linux | `ping -M do -s 1472 HOST`，然后二分那个尺寸 | **不分片**就能穿过的最大包 |
| macOS | `ping -D -s 1472 HOST` | 同上 |
| Windows | `ping -f -l 1472 HOST` | 同上 |

**为什么那个数字是 1472 而不是 1500：** 那个参数设的是载荷，而首部压在上面。
**不要背它 —— 去二分。** 你要的是那个边界，而那个边界会告诉你路径里是哪一种封装。

**一次通过排除掉什么：** MTU，连同整个*能用到要搬数据为止*那一类问题。**而一次失败告诉你的
比一个修复更具体**：它断在哪个尺寸，那个尺寸就说出了开销，而那份开销就说出了那条隧道 ——
这也是为什么这一级会以同样的形状、带着更多级，在
[`service-mesh.md`](service-mesh.md) 和 [`kubernetes.md`](kubernetes.md) 里再次出现。

## 第 5 级 —— 现在你可以看了

只有到现在。四级排除挣来了它，而这个顺序的理由是经济上的而不是道德上的：
**一次抓包信息最多，而且读起来最贵。** 一上来就打开它，意味着读完一切，然后什么都没找到。

| 在哪 | 那条命令 | 它回答什么 |
|---|---|---|
| Linux / macOS | `tcpdump -ni IFACE host HOST and port PORT` | 那个包有没有出去，以及回来了什么 |
| 云上 | 那个网卡的 flow log，按同一个五元组过滤 | 在你贴不上去的地方，同一个问题 |

**让这一级变短的那门纪律：** 你是带着一个假设到达的，因为四级已经把别的可能排除掉了。抓包是为了
**确认或者杀死那个假设**，然后就停。一次没有假设就打开的抓包，是一项爱好。

## 这个顺序为什么是这个顺序

每一级都**比它下面那一级更便宜**，而且**比它下面那一级排除得更多**。这就是全部的设计，也是为什么
跳级是"贵"而不只是"不整齐"：直接跳到抓包，你就是在不知道哪些包要紧的情况下读包，而它们每一个
看起来都很有道理。

这也是为什么 *ping* 没有属于自己的一级。`ping` 回答的是*有没有什么东西回了一个 ICMP echo*，而
一次失败和一个路由问题、一条过滤、一台死掉的主机，以及一条单纯丢弃 ICMP 的策略，全都相容。
**它什么都排除不掉** —— 这不是一句反对你去跑它的论证，它是一句反对你去信它的论证。

## 诚实边界

🔨 **亲手做过。** 这是核心运维地面：CCNP 级别的路由与交换、多年拥有 DNS 和 DHCP、横跨办公室与
数据中心的防火墙与 VPN，以及 [`build-out/10`](../build-out/10-remote-access.md) 里那些失败路径。
那个拒绝与超时的段落和那个 MTU 特征，都是疤痕组织而不是读来的。

**刻意不在这里：** 这些工具各自接受的每一个参数、没有列出的平台上的等价物，以及包级协议分析。
那正是这篇笔记[被收窄掉的那份参考](../docs/questions.md#边界)，而那次收窄就是重点 ——
一条逐级的命令服务于那架梯子，而一份参考会用"回忆"取代它。
