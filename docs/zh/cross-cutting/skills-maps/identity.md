# 身份与访问 —— 主题技能图

> 一个主题，横切每一个平台。实质内容住在
> [`cross-cutting/identity-iam.md`](../identity-iam.md) —— 这是它的可勾选版本。
> 约定、分层的锚，以及那条标记规则，在 [`README.md`](README.md) 里。

分层锚在**这项技能能走多远**上：**Core** 在全部七个平台上都成立，**Working** 在多数平台上成立、
而你必须知道自己在哪一个上，**Depth** 是那些平台确实互相不同意的地方。**当你做得到它、并且解释
得出它的故障模式**时才勾上一个框。

身份是需求信号里最密的那个簇，也是一个错误答案最不可见的那一个：一条过宽的授予看起来和一条正确的
一模一样，直到有人用了它。

## 目录与那个事实来源 🔨

- [ ] **Core** —— 点名那**一个**判定一个人存在的系统，以及当它说这个人不再存在时，下游会发生什么。
- [ ] **Core** —— 用户、组、OU、属性 —— 以及为什么基于组的访问是唯一熬得过规模的东西。
- [ ] **Core** —— 在它发生**之前**，逐个依赖系统说出当目录够不到时什么会坏。
- [ ] **Working** —— 混合：一个本地目录同步到一个云上目录，哪些属性在流动、往哪个方向，以及一次
  同步冲突长什么样。
- [ ] **Working** —— 两个都认为自己是权威的目录 —— 在它成为一个项目之前先认出这个形状。
- [ ] **Depth** —— 不停机地迁移那个事实来源：共存、切换，以及那个没人规划的回滚。

## 认证与授权 🔨

- [ ] **Core** —— 在每一次对话里都把那两个问题分开 —— *你是谁*和*你可以做什么*。把它们混为一谈，
  是多数身份困惑的根。
- [ ] **Core** —— MFA 的各种因子和它们真实的强度排序；为什么短信是一个因子，而且仍然是一个弱的。
- [ ] **Core** —— 会话寿命、token 过期，以及那次悄悄让一个已被回收的用户保持登录的刷新。
- [ ] **Working** —— 无密码与 FIDO2/WebAuthn：到底什么是抗钓鱼的，以及为什么。
- [ ] **Working** —— 读一份认证日志，并把一次失败的登录，和一次成功登录之后被拒绝授权，分开。
- [ ] **Depth** —— Token 重放与同意钓鱼 —— 那些从来不碰密码的攻击。

## 联合与 SSO（SAML / OIDC） 🔨

- [ ] **Core** —— 把那条流画出来：SP/RP、IdP、断言或 token，以及谁信任谁。
- [ ] **Core** —— 为一个给定应用在 SAML 与 OIDC 之间做决定并说出理由 —— 不是按偏好，是按那个应用
  支持什么。
- [ ] **Core** —— 调试那四个经典的联合失败：时钟漂移、entity ID / audience 错了、证书过期、
  属性或 claim 不匹配。
- [ ] **Working** —— 把 claim/属性映射到目标实际会去评估的那些角色上。
- [ ] **Working** —— 跨一条互联的双向信任：OIDC issuer、subject 映射、JWKS 的可达性。
- [ ] **Depth** —— 在一个活着的联合上轮换签名证书，而不在轮换途中把那些会话踢掉。

## 自己跑一个 IdP 🧭

- [ ] **Core** —— 说出当这个 IdP 变成你的之后，你接下了什么：它现在是你所运维的爆炸半径最大的
  那个系统。
- [ ] **Core** —— 先设计它的可用性 —— 别的每一个系统的登录都依赖它，所以它的停机不是它自己的。
- [ ] **Working** —— 签名密钥的生命周期、存储与轮换。
- [ ] **Working** —— 给它做备份，并且**恢复它**：一次 IdP 恢复是一次身份连续性演练，不是一次数据库
  演练。
- [ ] **Depth** —— 升级一个活着的 IdP；并且在选择自己跑它之前，先知道对着一个托管方案的那份诚实
  成本对比。

## SCIM 与入转离生命周期 🔨

- [ ] **Core** —— 把 J、M、L 三个都自动化。**离职是那个会被跳过的**，也是唯一一个后面挂着一个
  审计师的。
- [ ] **Core** —— 说出 SCIM 做了什么 SSO 没做的事：SSO 回答人怎么登录，SCIM 回答账号怎么诞生、
  怎么终止。
- [ ] **Core** —— 端到端追一次*转岗* —— 那个悄悄累积权限的案例，因为新访问被授予了，而旧的没被
  移除。
- [ ] **Working** —— 在 SCIM 够不到的那些系统上做停用，并且在你需要那份清单之前先把它们列举出来。
- [ ] **Working** —— 把目录对着每一个下游系统对账，并解释每一处差异。
- [ ] **Depth** —— 外包人员、服务账号和共享邮箱 —— 那些这条生命周期当初没为它们设计、而现在仍然
  拥有的主体。

**Prove it：** [`toolbox/user-lifecycle`](../../toolbox/user-lifecycle/)

## RBAC 与最小权限 🔨

- [ ] **Core** —— 为一件任务写一条**受限的**策略，并论证它为什么是最小的。
- [ ] **Core** —— 主体、角色、策略、范围 —— 把这四个映射到你面前那个平台上。
- [ ] **Core** —— 读一次**被拒绝的**请求并解释那次拒绝：哪条规则、在哪个范围上、按什么顺序被
  评估的。
- [ ] **Working** —— 默认拒绝与显式拒绝的优先级，以及那条会覆盖一条本地允许的组织级边界。
- [ ] **Working** —— 同时存在的两个授权平面 —— 一个目录角色和一个资源角色，或者云 IAM 和集群
  RBAC —— 在这里一个平面上的授予，对另一个平面什么都没说。
- [ ] **Depth** —— 从使用证据、而不是从一个猜测，把一个已经过宽的角色调回合适的尺寸。

**Prove it：** [`aws/iam-deny-by-default`](../../../../platforms/aws/labs/iam-deny-by-default/) ·
[`azure/global-admin-is-not-owner`](../../../../platforms/azure/labs/global-admin-is-not-owner/) ·
[`gcp/gke-iam-vs-rbac`](../../../../platforms/gcp/labs/gke-iam-vs-rbac/) ·
[`oci/a-compartment-is-not-an-account`](../../../../platforms/oci/labs/a-compartment-is-not-an-account/)

## 条件访问与设备信任 🔨

- [ ] **Core** —— 把一条策略表达成*信号 → 决定*：用户、设备、位置、风险 → 允许、阻断，或者要求
  更多东西。
- [ ] **Core** —— **绝不要写一条能把你自己锁在外面的策略。** 每一次，在保存之前先把一个
  break-glass 账号排除掉。
- [ ] **Core** —— 读一份登录日志，并说出是哪条策略生效了、为什么。
- [ ] **Working** —— 把设备合规当成一个信号，以及那条必须先存在的纳管路径。
- [ ] **Working** —— 把 report-only 模式当成强制执行之前的默认 —— 并且真的去读那份报告。
- [ ] **Depth** —— 那些完全绕过策略的旧式认证路径，以及在攻击者之前把它们找出来。

**Prove it：** [`labs/m365-conditional-access-lockout`](../../../../cross-cutting/labs/m365-conditional-access-lockout/)

## 特权访问与 break-glass 🔨

- [ ] **Core** —— 把日常账号和特权账号分开，先从你自己开始。
- [ ] **Core** —— 设计一个 **break-glass** 账号：它绕过什么、那份凭据住在哪，以及它被使用时谁会
  被告警。
- [ ] **Core** —— Root/全局管理员的卫生：MFA、没有密钥、不日常使用、被监控着。
- [ ] **Working** —— 带审批和过期的即时提权，取代常驻权限。
- [ ] **Working** —— 按日程测试那条 break-glass 路径。一条没测过的是一个信念，不是一项控制。
- [ ] **Depth** —— 那些不留下任何有用审计轨迹的最高权限操作 —— 把它们找出来，然后做补偿控制。

## 访问复审与权限蔓延 🔨

- [ ] **Core** —— 回答*"谁能看见这个？"* —— 并且知道读那些权限回答不了它，因为一条分享链接是一条
  没有任何复审会走的授权路径。
- [ ] **Core** —— 跑一次能找出陈旧账号和过宽授予、并且产出**证据**而不是一句断言的复审。
- [ ] **Working** —— 列举通向一个资源的**每一条**授权路径：直接、组、嵌套组、链接、继承，以及
  API token。
- [ ] **Working** —— 认出那个形状：一次时点复审如实通过了，而这片估算面仍然是错的 —— 因为缺失的
  那项控制是一个**过期期限**，不是一项访问控制。
- [ ] **Working** —— 把两个不一致的系统对账，并判定哪一个是对的；你挑的那个连接键决定了这个答案里
  有多少是虚构的。
- [ ] **Depth** —— 让复审证据可审计：可复现、有日期，并且可归属到一个决策者。

**Prove it：** [`labs/permission-sprawl`](../../../../cross-cutting/labs/permission-sprawl/) ·
[`labs/transcript-retention`](../../../../cross-cutting/labs/transcript-retention/)

## 工作负载身份 🧭

- [ ] **Core** —— 给一台机器一个身份而不是一把密钥，并说出为什么一把轮换过的密钥仍然是一把密钥。
- [ ] **Core** —— 短寿命凭据优于长寿命密钥 —— 并且把你估算面里已经存在的那些长寿命密钥找出来。
- [ ] **Working** —— 在每个平台上把一个身份挂到一个计算资源上，并列举那台主机上还有谁因此够得到它。
- [ ] **Working** —— 用 OIDC 把一个工作负载从一朵云联合进另一朵，并且不存任何密钥；在信任条件和
  subject claim 上调试它。
- [ ] **Depth** —— 盘点每一个非人主体和它的爆炸半径。这份清单通常比那份人的更长，而且被复审得更少。

**Prove it：** [`aws/01-scoped-identity-inventory`](../../../../platforms/aws/labs/01-scoped-identity-inventory/)

## 那个"你到底能不能运维它"的测试

每一个 **Core** 框被勾上，都意味着身份可迁移：词汇逐平台变，问题不变。**Working** 框是那些平台不再
一致的地方 —— 两个授权平面、混合同步、跨云联合 —— 也是一份单平台直觉最自信地错着的地方。

十个小节里有五个指向某样可跑的东西，那是这个仓库里密度最高的，而这不是偶然：身份是这个仓库的
lab 集中的地方，因为它是一个错误从内部最看不出来的地方。那些没有演练的小节 —— 目录、认证/授权、
联合、自己跑一个 IdP、特权访问 —— 是你最该怀疑自己那份自信的那几个。
