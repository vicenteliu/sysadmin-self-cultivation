> 每个平台目录都带一张[技能图](../../platforms/aws/skills-map.md)：
> **一个平台，横切每一个主题。** 这个目录是它的转置 ——
> **一个主题，横切每一个平台。** 同样的勾选框格式、同样的问题（"你**做**得到吗？"），
> 旋转九十度。

那次旋转就是重点。一张平台图回答*"关于 AWS 我还有什么不知道？"* 一张主题图回答一个平台图在结构上
问不出来的问题：**"我关于网络所知道的，有多少能跟着我走，又有多少其实只是 AWS？"**

## 那些图

| 图 | 覆盖什么 | 标记 |
| --- | --- | --- |
| [`networking.md`](networking.md) | 地址、路由、L2/overlay、DNS、DHCP、过滤规则、负载均衡、TLS、远程访问、流分析、跨云 | 🔨 ×9 · 🧭 ×2 |
| [`identity.md`](identity.md) | 目录、AuthN/AuthZ、联合与 SSO、跑一个 IdP、SCIM/JML、RBAC、条件访问、特权访问、访问复审、工作负载身份 | 🔨 ×8 · 🧭 ×2 |

更多主题会按 [`../../ROADMAP.md`](../../ROADMAP.md) 同样的需求顺序跟上。这两个先来，是因为它们
是需求信号里最密的两个簇，而且因为它们两个之间承载了其他主题所假定的大部分东西。

## 这里的分层意味着不一样的东西

一张平台图把它的分层锚在那个平台**内部** —— *"Core：没有这个你管理不了 AWS。"* 一张主题图没有
这样一个锚，所以它用另一个：**这项技能能走多远。**

| 层 | 锚在哪 |
| --- | --- |
| **Core** | 在全部七个平台上都成立。这个概念熬得过每一次改名；变的只是那个名词。 |
| **Working** | 在多数平台上成立。真实的差别是存在的，而你必须知道自己在哪个平台上。 |
| **Depth** | 平台特有的，或者那些平台确实互相不同意的地方。这就是那个可迁移模型停下、而阅读开始的地方。 |

从头到尾读一张填好的图，它同时告诉你两件事：接下来学什么，以及当平台变了的时候
**你能留下多少**。没勾上的 Core 框是最贵的那些 —— 那儿的一个缺口是处处都缺。

**当你做得到它、并且解释得出它的故障模式**时才勾上一个框 —— 不是在你读过它的时候。和平台图同一条
规则。

## 标记坐在小节上，不坐在这个目录上

平台图内部**不带** 🔨/🧭 标记；那份诚实标记住在整个平台上。那在那边行得通，在这边行不通，因为一张
主题图几乎总是混合的：网络**设计**是 🔨，而在同一个文件里网络**监控**是 🧭。一个压在文件上的单一
标记只能写成"mixed"，而那正是 [`WHY.md`](../../WHY.md) 存在去拒绝的那种含混。

所以在这个目录里，标记坐在**小节**上 —— 那个让这句声称仍然为真的最细粒度，再细就不行了。单个勾选框
保持不带标记：一页上一百个字形就不再是一个信号，而变成了壁纸。

**那些平台图没有变。** 这个先例只在这条轴上被打破。

## 当两个主题都想要一项技能时，它住在哪

**一项技能属于它所作用之物的那个主题，不属于它如何作用的那个主题。**

网络监控就是那个逼出这条规则的案例。它是监控，所以一张可观测性图迟早会想要它；它同时也是"不知道
一张路由表和一个五元组是什么就读不懂"的。归到可观测性下面，它会在一个三支柱的框架里被稀释成
"网络也需要监控"。所以它被永久地归在这里 —— 而未来那张 `observability.md` 覆盖主机层和应用层，
并横向链过来，而不是把它吸收掉。

同一条规则把证书生命周期送到这里（它作用于传输），而不是送到一张未来的安全图；并把条件访问送到
[`identity.md`](identity.md)（它作用于一次登录），而不是送到 endpoint。

## 不是第七条轴

[ADR-0001](../../docs/adr/0001-the-build-out-is-a-route-not-a-seventh-axis.md)
在 `build-out/` 提出这个问题时就把这个模式定下来了：这个仓库的轴是*材料的各个面*，而一个不教任何
新页面的东西不是一个新的面。这些图不教任何新页面。每一个框都指进一条轴去取实质内容，和一个
build-out 步骤完全一样 —— 这也是为什么它们住在 `cross-cutting/` 里面，而不是它旁边。

那个后果和 ADR-0001 点名的是同一个：**一个需要一段话去解释的框，是一个放错了地方的框。**
把解释挪到那条轴上，然后链过去。

## Prove it

当仓库里有一样可跑的东西对应它时 —— 一个 [lab](../labs) 或一个
[`toolbox/`](../../toolbox/) 工具 —— 一个小节会以一行 `**Prove it:**` 结尾。没有的小节就没有；
那是信息，不是疏漏。

和 [`build-out/GAPS.md`](../../build-out/GAPS.md) 不一样，**这里缺失的可跑证据不被记为一个缺口。**
那份清单是从一个具体场景派生出来的，并且刻意保持狭窄；一份来自另一条轴的愿望清单，会悄悄改变它
的含义。
