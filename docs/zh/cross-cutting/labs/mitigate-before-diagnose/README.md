# Lab —— 先缓解再诊断，以及那两个让它不再成立的地方

> 🌐 **语言：** [English（默认）](../../../../../cross-cutting/labs/mitigate-before-diagnose/README.md) · **中文**
>
> ⚠️ 本项目**默认语言为英文**，`cross-cutting/labs/mitigate-before-diagnose/README.md` 是"事实来源"。本页中文是多语言支持的一部分，可能略滞后于英文版；两者不一致时以英文为准。

---

> **输入：** 无 · **输出：** 两种策略下的期望停机和最坏停机、那个交叉点，以及那个让它反转的风险
> 惩罚 · **风险：** 无 —— 不用系统、不用服务、不用凭据 · **root：** 不需要

**目标：** 拿 [`incident-response.md`](../../incident-response.md)的那句中心主张 ——
*先缓解再诊断，那个把高手区分出来的唯一直觉* —— 然后**去测量它，而不是复述它。**

**你会练到：** 把一个运维直觉说得足够精确，精确到它可能是错的，然后去找出它在什么条件下是错的。

## 这个 lab 为什么是纯本地的

一次事故是一个分布之下的决定：一组成因，各有一个找到它的时间和一个修好它的时间，再加上一个覆盖其中
一部分的通用缓解手段。这完全可以用算术表达出来，而把它表达出来，正是把一句口号变成一句带边界的主张
的方式。

这个 lab 所取代的那份规格要求一次桌面推演和一次 game day。两个都值得做，而两个都不是 lab ——
它们是[引导式走查](../../../CONTEXT.md)，因为没有任何东西能断言你做过它们。那份规格里可建模的东西
是它底下那句话，而这个 lab 就是那句话。

不用系统、不用服务、不用凭据、不用 `pip install`。纯标准库，**完全确定性** —— 每一个数字都是在那个
成因分布上的一个精确期望，而不是一次模拟，所以下面那些数字就是你会拿到的数字。

## 跑它

```bash
python3 cross-cutting/labs/mitigate-before-diagnose/mitigate_drill.py
python3 cross-cutting/labs/mitigate-before-diagnose/mitigate_drill.py --break-it
```

exit code `0` 表示关于这个教训的每一条断言都成立。

## 你会看到什么

1. **先缓解省下九分钟的平均停机**，在一个通用缓解手段按概率覆盖了 76% 成因的分布上。那就是那句
   口号，被确认了 —— 而它是这里最没意思的一样东西。

2. **尾部往另一个方向动，而且恰好是六分钟。** 诊断优先下最糟的那次事故是六十分钟；缓解优先下是
   六十六分钟。多出来的那部分，恰好就是那个缓解窗口，而它花在了一个通用缓解手段本来就覆盖不到的
   成因上 —— 而**你会遇到的最糟的那次事故，按定义就是其中之一。**

   那就是那笔交易，而且方向是对的：**在罕见事故上付出一个小的、有界的、已知的代价，来把一个大的
   代价从每一次常见事故里移除。** 一个只提那个收益的版本，就是在推销。

3. **那个交叉点：大约 40%。** 在那个覆盖率以下，诊断优先才是更好的判断。这个数字让这条建议变得
   *可证伪*，而不只是为真，而它才是值得带走的那个 —— 因为在一片新估算面里，那个诚实的问题不是
   *我该不该先缓解*，而是**我的缓解手段覆盖得了这里真正会坏的东西里的足够多吗**。

4. **一个可能把事情弄得更糟的缓解手段，在大约十分钟处让它反转。** 超过那个期望惩罚，缓解优先就是
   错的判断。所以这句口号悄悄依赖于一个便宜且可靠的缓解手段 —— 而那恰恰是那次
   [演练过的恢复](../../../the-stack/labs/04-backup-not-snapshot/)和一次练过的故障切换买给你的
   东西。**它们不是针对那次事故的保险；它们是让这个直觉成立的那样东西。**

5. **增加应急人员在大约五个人处不再划算**，因为每加一个人都得被告知已知的东西，而"告知"这件事花的
   是和"修"同一批分钟。过了那儿之后，能买来更多的不是又一双手 —— 而是**把协调工作从应急人员的分钟
   里拿出去**，而那正是一个事故指挥官的全部岗位描述。那一章把 IC 称作一个不动手修的协调者；这就是
   为什么那是一个角色，而不是一份额外开销。

6. **`--break-it` 走诊断优先**，而它不是一个稻草人。它是一个细心的工程师会做的事、它在每一次复盘里
   都站得住脚，而且**除非你事先做过别的决定，否则在压力之下你就会这么做。** 一条断言挂掉，而它是
   那条平白的：平均每一次事故多停九分钟。

## 验证（别光信这个脚本说的）

- **把 `MITIGATION_MINUTES` 设成 `1`**，看着那个尾部惩罚缩到一分钟。步骤 2 里那笔交易完全就是那个
  窗口的大小，而这正是"把缓解做得快，而不是做得聪明"的论据。
- **把 *bad deploy*（先验概率最大的那个）的 `generic_works` 翻成 `False`** 再跑。覆盖率掉到那个
  交叉点以下，而这条建议就反转了，方向和这个模型说的一致。
- **把那个分布换成你自己估算面的。** 六个带先验概率的成因，是一件你花一个下午、从去年那些事故里就
  能写下来的事，而这么做会把这里的每一个数字都换成一个关于你自己的数字。
- **把步骤 5 里那个协调系数设成 `0`**，然后看着应急人员线性扩展。他们从来没有过。那个系数是
  *被写明的、而不是被推导出来的*，而这份 README 是刻意这么说的 —— 那个发现是"存在一个天花板"，
  不是"它在哪儿"。

## 重点

**一个你没法证伪的直觉，就是一个习惯。** *先缓解再诊断*是好建议，而它是**有条件的**好建议 ——
一个覆盖得了你足够多成因、并且失败时代价不大的缓解手段。这两条都是你那片估算面的属性、而不是这条
建议的属性，而且两条都能在一个下午里测出来。

那一章点名的那个高手直觉，其实并不是*先缓解*。它是在呼机响之前就知道**你打算做哪一个、以及为什么**
—— 因为那不是一个你能在凌晨三点、盯着一张红掉的图的时候做得好的决定。
