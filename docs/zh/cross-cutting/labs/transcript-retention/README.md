# Lab —— 通过了权限那个 lab 的那片估算面，正是在这个 lab 上失败的那一片

> 🌐 **语言：** [English（默认）](../../../../../cross-cutting/labs/transcript-retention/README.md) · **中文**
>
> ⚠️ 本项目**默认语言为英文**，`cross-cutting/labs/transcript-retention/README.md` 是"事实来源"。本页中文是多语言支持的一部分，可能略滞后于英文版；两者不一致时以英文为准。

---

**目标：** 展示一次不含任何错误的治理失败。没有任何东西配错了、没有任何策略被违反、没有任何复审会
标出任何东西，而三年之后，一场私密对话能被三倍多的人读到 —— 包括一个当时不在那个房间里、却被那场
对话谈论着的人。

**你会练到：** [build-out 第 12 步](../../../build-out/12-meeting-rooms-av-and-uc.md)里*能够*被做成
可跑的那一半 —— 录像和转录落在哪儿、谁读得了它们，以及能读多久。第 12 步是这一系列里唯一一步，
对"这里面有多少是 AI"的答案是*相当多*，而这就是那件事所改变的东西。

## 这一篇坐在哪儿，以及它为什么不是第二个 lab 07

[`permission-sprawl`](../permission-sprawl/) 问的是**谁能看见这个**。那是一个关于某个瞬间的问题，
而它把这个问题回答得很好。它那条建议 —— 分享给组、绝不分享给个人、不留开放链接 —— 在这里被一字
不差地遵守着。

这个 lab 问的是一个瞬间装不下的那两个问题：

- 在这份产物的**整个生命周期**里、随着一个正确的组不断变大，谁能看见它
- 他们正在读的东西，还**对得上**任何东西吗

**按 lab 07 建议的方式去做，正是让这件事发生的原因。** 用组分享是正确的，而一个正确的组会变大。
这个失败不存在任何一个能被更好的 ACL 防住的版本。

## 这个 lab 为什么是纯本地的

两个时钟和一个集合。组成员关系在推进，保留期在到期，而那份读者名单是曾经在那个组里的每一个人的
并集 —— 这里面没有一样需要一套办公套件、一个租户、凭据或者 `pip install`。Python 标准库，CI 也
跑得了。

## 跑它

```bash
python3 cross-cutting/labs/transcript-retention/retention_drill.py
```

exit code `0` 表示关于这个教训的每一条断言都成立。

## 你会看到什么

1. **第 0 天是正确的。** 那份转录分享给了 `group:project-atlas`，零次单独授予，零条开放链接。
   这个夹具里哪儿都没有任何配置错误。
2. **读者在变多，而没有人授予过任何东西。** 六个人在那个房间里；**21** 个人能够读到那个房间里说过
   的话，横跨 **0** 次授予。那个组今天有 **18** 个成员 —— 比曾经持有过访问权的那 21 个少，因为
   离职的人不会"未读"回去。一份成员清单，是一个只会累加的集合的一张快照。
3. **那些复审通过了。每一次。而且是如实通过的。** 三年里四次访问复审、四个干净的结果，没有一个是
   错的。一项在每一个被求值的瞬间都正确的控制，仍然可能对那些瞬间之间的*区间*是错的，而一次访问
   复审没有任何表达区间的语法。
4. **那个源头比从它派生出来的东西先过期。** 那份录像带着一个 30 天的平台默认值；那份转录和那份摘要
   什么都不带。那份转录在被建模的日子里有 1096 天*读得了*，却只有 31 天*核得了* —— **3%**。
   贵的那份产物按一个默认值过期，而便宜的那份不过期，所以那份本来能敲定归属的记录，是先没的那份。
5. **那份摘要错了，而且是安静地错。** `mei` 说的一句话被归到了 `sofia` 头上 —— 一个普通的说话人
   分离错误。它有三十天是核得了的。它现在就是"当时说了什么"的那份记录。
6. **现在是谁在读它。** 15 个当时不在那个房间里的人，其中一个是 `priya` —— 她在里面被点了名、被
   用第三人称谈论着，而她是在第 **700** 天通过普通的入职流程加入这个项目的。她读得了一场关于她
   自己的对话，包括一句被归错到另一位同事头上的话。当初覆盖那份录像的同意，覆盖的是三年前一个房间
   里的六个人。

## 验证（别光信这个脚本说的）

```bash
python3 .../retention_drill.py --break-it   # exit 1
```

`--break-it` 用时点访问复审来治理 —— 也就是每一个组织实际在跑的那项控制。**它没有错。** 它正确地
读了一个正确的状态，并且每一次被问到时都返回正确的答案。

四条断言挂掉了，而那些失败消息就是重点：这套机制看不见那个漂移、注意不到那个源头已经过期，也点不
出 `priya` 的名字。不是因为它把那些问题答错了 —— 而是因为**它根本没有一个问题的答案会是它们中的
任何一个。**

想再往前一步，把 `TRANSCRIPT_RETENTION = 365`，给那份转录一个 365 天的保留期。累计读者数从 21 掉
到 **11**，`no_expiry` 和 `unverifiable` 这两条发现消失了，而 `priya` 根本就没拿到过访问权 ——
她在第 700 天加入，而那份文档在第 365 天就不存在了。

这个演练会带着**六**条挂掉的断言 `1` 退出，而这是正确的，也值得坐下来好好待一会儿：它断言的东西
大部分是关于*无限期保留*的断言，所以设一个保留期并不会让这个失败变小，它是把被测量的那样东西删掉
了。一个数字，设一次，就在录制按钮被按下的那一刻。

## 重点

**那项缺失的控制是一个过期期限，不是一条权限。** 如果你对一份转录问的唯一问题是谁能看见它，
那你会一直拿到正确的答案，而与此同时那份暴露在不断变大。

三件要带走的事：

- **每一次录制都是一个关于接下来三年的决定**，由那个按下按钮的人做出，而通常他并不知道那是什么。
  设保留期的地方是那个平台默认值，在第一场会议之前，不是在那次事故当中。
- **要问累计读者数，不是当前成员数。** "谁能看见这个"有一个更小、也更安慰人的答案，而"谁曾经能够
  看见这个"才是转录里那个人会问的那个。
- **拿一份派生产物的保留期去对照它的源头。** 摘要、转录和笔记经常活得比它们来自的那份录像还久，
  这意味着那个权威版本，正是没有人核得了的那一份。

没有。这个演练把所有东西都放在内存里，不写任何文件。
