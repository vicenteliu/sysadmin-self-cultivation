# Lab —— 六个里覆盖了六个，而 EDR 一个人扛着其中三个

> **输入：** 无 · **输出：** 那张矩阵，然后是它表达不了的那四件事 · **风险：** 无 —— 不用工具、
> 不用扫描器、不用凭据 · **root：** 不需要

**目标：** 做 [`working-with-security.md`](../../working-with-security.md)所要求的事 ——
在每一个 kill-chain 阶段点名你所拥有的那项控制 —— 然后**去读那张答卷藏起了什么**，而那是另一个
练习，也是唯一真正改变了什么的那个。

**你会练到：** 注意到一张控制矩阵是按*阶段*索引的，而每一个值得问的问题都是关于一项*控制*的。

## 这个 lab 为什么是纯本地的

覆盖是集合算术：阶段、控制，以及谁覆盖谁。这里没有什么可扫描的，而且扫描也回答不了这些问题 ——
一个姿态工具报告的是逐资源的发现，而这里的失败在于那份*摘要的形状*。

这个 lab 所取代的那份规格说的是*不用工具，只用判断*，而它是对的。它没说的是：那份判断会产出一张
表格，而**那张表格的格式就是那个陷阱**。那一部分是可建模的，所以它被建模了。

不用工具、不用扫描器、不用凭据、不用 `pip install`。纯标准库，完全确定性。

## 跑它

```bash
python3 cross-cutting/labs/one-control-three-stages/coverage_drill.py
python3 cross-cutting/labs/one-control-three-stages/coverage_drill.py --break-it
```

exit code `0` 表示关于这个教训的每一条断言都成立。

## 它建模的那片估算面

普通而称职，不是差：一条补丁流水线、邮件过滤、EDR、MFA、一个密钥管理器、集中日志、测试过的备份 ——
**外加两项存在于设计里、图里和审计答卷里、却不存在于这片估算面里的控制**：最小权限和网络分段。
最后那一对是这个模型里最真实的东西。

## 你会看到什么

1. **六个阶段里有六个有答案。** 这正是这张矩阵被建出来要展示的东西，而它是真的。

2. **十一行被填满的格子，靠的是七项不同的控制。** 一张矩阵每个阶段一行，所以一项回答了三个阶段的
   控制会被写三遍，而且**被数三遍**。这片估算面不是那样运作的。它是一次性失败的。

3. **在三个阶段上，EDR 是唯一的预防性控制** —— 执行、提权和横向移动。如果它失效、被绕过，或者根本
   没装在那台要紧的主机上，六个阶段里就有三个同时门户大开。

   **矩阵这个格式里没有任何东西会问这个问题**，因为矩阵是按阶段索引的，而这是一个关于一项控制的
   问题。它是那份输出里价值最高的那一样东西，而它需要的是一个没有任何模板有的列。

4. **最后那个阶段不是被防住的。它是被熬过去的。** 控制有**三种**，而这张矩阵给它们三个只留了一列：

   | 种类 | 攻击者体验到什么 |
   |---|---|
   | **预防** | 他们进不来 |
   | **检测** | 他们进来了，而你发现了 |
   | **恢复** | 他们进来了、**得手了**，而你事后回来 |

   测试过的备份是第三种。它们是任何一片估算面里最有价值的控制之一，而它们**并不防止影响** ——
   勒索软件照样跑起来、数据照样被加密，然后你去恢复。在"影响"那一行写上*测试过的备份*、然后宣布这
   个阶段已覆盖，说的是攻击者在那里失败了。他们没有。

5. **那两项没做完的控制解释了第三条发现。** 最小权限和分段本来各自都会在 EDR 那三个阶段里的两个上
   提供第二项控制。所以**在纸面上，EDR 从来就不是一个人扛着它们** —— 而这恰恰就是为什么没有人注意
   到，在这片估算面里它就是。

6. **`--break-it` 按阶段计分**，而这不是一个稻草人。它就是每一张控制矩阵、每一份审计答复和每一份
   安全问卷的格式，而它报告 **6/6**。两条断言挂掉，而它们是同一类的：那套计分方式没有一列容纳那个
   问题，所以它没法是错的 —— 它只能是沉默的。

## 验证（别光信这个脚本说的）

- **把 `least privilege` 设成 `in_place=True`** 再跑。EDR 的爆炸半径从三个阶段掉到一个，而这是
  这个文件里最便宜的一次改动 —— 也就是这个 lab 真正产出的那条建议。
- **把 `tested backups` 改成 `kind="prevent"`**，看着步骤 4 报告每一个阶段都被预防了。那一处编辑
  就是被描述的那整个错误，而它也正是一张控制矩阵默认会做的那处编辑。
- **加上第二项 EDR 类的控制**，只覆盖执行，然后看着那个爆炸半径收窄、而没有任何一个阶段的*覆盖*
  发生变化。覆盖从来就不是那个变量。
- **把这片估算面换成你自己的。** 九项控制和六个阶段是一个下午的活，而那份输出是一句你可以递给安全
  团队的话：*这些是那些阶段、这是扛着每一个的东西，而这一项控制扛着三个。*

## 重点

**一张控制矩阵是按错误的东西索引的。** 它问的是*这个阶段覆盖了吗*，那有一个让人安心的答案，而它
从来不问*这份覆盖是靠着什么*，那个没有。

三个这个格式表达不了、而都能在一个下午回答的问题：

- **哪一项控制一旦失效，会打开最多的阶段？** —— 那个爆炸半径，它是一项控制的属性，而它没有行。
- **预防、检测，还是恢复？** —— 三种不同的主张共用一个词。
- **是设计过的，还是部署了的？** —— 这两者在一份审计答卷里区分不开，而在一次事故当中完全区分得开。

而那份规格所要求的那次交接也因此变好了。*我们六个里覆盖了六个*对一个 SOC 分析师没什么用。
*EDR 是我们在三个阶段上唯一的预防性控制、影响那一层只有恢复，而最小权限是设计过但没部署的* ——
才是他们真正需要的那两句话，而那**就是**在与安全协作。
