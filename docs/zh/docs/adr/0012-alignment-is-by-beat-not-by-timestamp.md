# 对齐按拍，不按时间戳

> 🌐 **语言：** [English（默认）](../../../../docs/adr/0012-alignment-is-by-beat-not-by-timestamp.md) · **中文**
>

[楼面](0011-the-floor-renders-the-reference-office-and-may-not-compute-it.md)随着叙述推进而推进：
镜头跟着主角走、缩放切换档位、一个物体在被点名时亮起来。总得有什么东西说出*什么时候*。

每一个视频和播客工具都用时间戳来回答这件事，而时间戳在这里行不通。
[ADR-0009](0009-the-walkthrough-ships-its-script-not-its-audio.md) 没有把音频放进这棵树，这意味着
没有一段单一的录音可以拿来对时 —— 有多少位读者就有多少条时间线。一位用自己凭据生成语音的听众拿到
的是他那个引擎的声音、他的语速和他的语言；作者已发布的那一集又是第三条时间线。一个时间戳恰好只
对其中一条正确。

## 决定

**一篇走读在物理上被划分成拍，而楼面按拍被提示。**

一拍是**一段话、一次 TTS 调用、一个音频片段、一个楼面状态**。一个播放器在一个片段结束时推进楼面。
任何地方都不记录时长，所以没有任何时长可能是错的。

拍在 Markdown 里由一条携带**稳定 id** 的 HTML 注释来分隔：

```markdown
<!-- beat: coverage-not-capacity -->
```

GitHub 不渲染它、viewer 不渲染它，而一个语音引擎永远收不到它 —— 所以那个可见的文件仍然只剩下那些
会被念出来的词，正如 ADR-0009 所要求的。每一拍的楼面状态和物体绑定，住在同级的
`walkthrough/<episode>.floor.json` 里，用那个 id 作键。

**那个 id 是一个名字，绝不是一个序数。** 是 `coverage-not-capacity`，不是 `beat-17`。往一份
一百四十拍的稿子里插入一段话，绝不能静默地把它之后每一个提示都移动一位 —— 而它会是静默的，因为
一个指着错误拍的楼面，看起来和一个指着正确拍的楼面一模一样。

## 考虑过的选项

- **对着作者已发布的那一集用时间戳，并为其他所有人做一个滚动驱动的回退。** 被否决，因为它让作者
  那段录音成为那件被特权对待的产物，而每一份自行生成的都成了二等 —— 而这是在一个刚刚决定根本不
  交付录音的仓库里。它还把定时数据放进了这棵树，而它所描述的那些音频不在这棵树里，那是留错了一半。

- **来自浏览器语音 API 的语音边界事件。** 很吸引人：免费拿到词级同步。被否决，因为它把楼面绑到了
  一条特定的合成路径上。一位从一个托管 TTS API 生成音频文件的读者 —— 也就是这篇走读所为之而写的
  那个情况 —— 根本不会发出任何边界事件。

- **序数拍号。** 写起来更简单、读起来也更简单。按上面那个故障模式被否决：那次漂移是由一次普通编辑
  造成的、不产出任何错误，而且直到有人看完整整一集、注意到楼面慢了一拍之前，它都是不可见的。

- **不要楼面提示；让读者自己驱动。** 被否决，因为那会把叙述变成一份菜单。走读的形状是一条你不跳过
  的线，而那正是一个故事和一份参考之间的分野。

## 后果

- **任何引擎、任何声音、任何语言都能用，而且没有一个需要配置。** 这就是全部的重点：对齐的单位是
  *哪一拍*，而每一位读者都对此有共识，不管他的音频要花多久去把它说完。
- **一拍是楼面能作出反应的最小的东西。** 词级效果 —— 一个物体在点到它名字的那一个音节上亮起来 ——
  够不到，而且会一直够不到。那是一份真实的损失，为了上面那份可移植性而被接受。
- **拍 id 是一个接口，而给一个改名是一次破坏性变更。** `.floor.json` 引用它们，而在发布之后，
  一段没人能编辑的录音也引用它们。改名属于勘误，不属于整理。
- **那次发布冻结有一个天然的单位。** 因为片段是逐拍的，作者已发布的那一集就是同样那些片段拼接
  起来的 —— 所以一拍里的一次修正，是一个要重新生成的片段，不是一整段录音。它并不让一集已发布的
  内容变得可编辑，但它让下一集变便宜。
