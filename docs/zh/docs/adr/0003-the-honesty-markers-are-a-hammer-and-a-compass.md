# 诚实标记是 🔨 和 🧭，不是 ✋ 和 🧗

> 🌐 **语言：** [English（默认）](../../../../docs/adr/0003-the-honesty-markers-are-a-hammer-and-a-compass.md) · **中文**
>
> ⚠️ 本项目**默认语言为英文**，`docs/adr/0003-the-honesty-markers-are-a-hammer-and-a-compass.md` 是"事实来源"。本页中文是多语言支持的一部分，可能略滞后于英文版；两者不一致时以英文为准。

---

这个仓库里每一个模块都标出什么是**亲手做过的深度**、什么是**一条诚实的 ramp**。`WHY.md` 论证过
这个区分就是全部的重点，而 `README.md` 把它放在第十七行，在目录之前。因此这些标记是这个仓库里
被读得最多的字形 —— 它们在 104 个文件里出现了 591 次，而其中一个是一个陌生人看到的第一样东西。

它们曾经是 `✋` 和 `🧗`，而两个都是按它们的含义、而不是按它们读起来怎么样挑出来的。

## 决定

**亲手做过的深度是 `🔨`。一条经过验证的 ramp 是 `🧭`。** 其他标记 —— `✅` 完成、`🚧` 计划中、
`❌` 过度声称、`⚠` 警告、`🌐` 语言 —— 都不变。

这些标记同时在两个地方携带含义：一位扫过一张密表的读者看到的是一个字形，而一位在其中一个上停下来
的读者读到的是一句声称。`✋` 和 `🧗` 是为第二位读者造的，而对第一位失败了。

- **`✋` 读起来是*停*。** 它本意的含义是*亲手*——字面上就是那只手。但那只举起的手掌，在读者遇到
  它的几乎每一个语境里都是一个"停"的手势，而拯救它的那个双关只在一种语言里成立。一个承载着这个
  仓库中心承诺的标记，不能依赖一个双关。
- **两个都是人形**，所以两个都会带肤色修饰符、在每个平台上渲染得不一样，并且在单色回退时互相
  坍缩到一起。
- **它们的剪影是同一个形状。** 两个竖直的人形，在像 `✅ ✅ ✅ | 🧗 + Entra/身份 ✋` 这样的行里
  并排出现时，只有停下来看才分得开 —— 而那恰恰是一个扫描行标记绝不能要求的那一件事。

`🔨` 和 `🧭` 是物体，不是人形：没有肤色、没有变体选择符，而且是**一道实心的斜线对着一个圆** ——
一眼、任何尺寸下，都读得出是两样不同的东西。那些隐喻熬过了这次更换：一把锤子是这样东西被造出来
所用的工具，而一个指南针是你带进一片你没走过的地形的东西，而那正是这个仓库对一条 ramp 的定义。

## 考虑过的选项

- **用 `🛠️` 表示亲手做过的深度。** 因为一次**术语碰撞**而被否决。这个仓库有一条 `toolbox/` 轴和
  一个 `toolbox-picker` skill，而 `🛠️` 是*工具*和*设置*那个几乎通用的字形；它会把"我会做什么"
  和"这个仓库带了什么"归到同一个符号后面，而那是两句不同的声称。单个 `🔨` 读起来是*这是被锤出来
  的*，而不是*这儿有一套工具* —— 这个余量比听起来更窄，而它诚实的名字是一次判断，不是一次干净的
  胜利。

- **用 `⚒️` 表示亲手做过的深度。** 最先被选中，在 104 个文件里发布了出去，一天之后被纠正。它被
  留在这份记录里，是因为它失败的理由是这里最可迁移的东西 —— 见**那次纠正**。

- **用 `⚓` 表示亲手做过的深度。** 很晚才被否决，而在那之前它一直是那个推荐 —— 直到被核对的是那个
  **词**、而不是那个字符。那个字符没被用过；那个**词**被用过。**Anchor 已经是这个仓库表示"上手"
  的动词** —— `ai-workflow/how-i-use-ai-to-learn-and-operate.md` 把它编号为规则 2，
  *"把一切锚定到你已经知道的东西上"*，而四篇 `ai-ramp.md` 笔记都重复了它。把 `⚓` 指向深度，会把
  一个符号瞄准它那个词已经意味着的东西的反面，而且就在那个词被定义的地方三行开外。

- **给那条 ramp 规则改名，好把 `⚓` 空出来。** 否决。那条规则是好的，而且它有编号；为了给一个字形
  腾地方而挪动方法论的一块，把"什么服务于什么"倒了过来。

- **保留 `✋`/`🧗` 并在一份图例里解释它们。** 否决，而这正是这次更改存在去拒绝的那个选项。一个
  需要一条注释才能不被误读的标记，已经在唯一要紧的那一刻失败了 —— 就是它被放在那儿去熬过的那一
  眼。

- **换掉整套色板。** 否决。单是 `✅` 就出现了 261 次，而它的含义没有争议。在同一次改动里既换那些
  能用的符号、又换那些不能用的，会让那份 diff 变得读不了，而那个理由变得找不回来。

## 那次纠正

这个决定的第一个版本选了 `⚒️`（U+2692，HAMMER AND PICK）并附加了 U+FE0F —— 而这份文档在它自己的
后果里就是这么说的：*任何生成这些标记的东西都必须发出那个选择符*。那条指令被完全照做了，在全部
104 个文件里，而它不够。

**一个变体选择符只是*请求*表情呈现。它不创造一个彩色字形。** U+2692 默认是文本呈现，所以一个不带
它的彩色字形的字体，会把它渲染成一个小小的单色符号 —— 就紧挨着 `🧭`（U+1F9ED），一个到处都是彩色
的原生表情码点。结果比任何单独一个标记都糟：一对不对称的标记，其中一边读起来像标点。在 README 上，
这次更改看起来像是没发生过，而那正是它被抓住的方式。

它留下的那条规则短到不用重新推导就能施行：**一个需要选择符才能成为表情的码点，不是一个标记。**
从原生表情区间里挑，在那里颜色不是一个字体去做的决定。

`🔨` 是 U+1F528 —— 一个码点、没有选择符、到处都是彩色的。用慢办法学到这一点的代价，是在第一次
之后一天，对 103 个文件里的 327 处再做一次重写。

## 后果

- **这次重写是 104 个文件里的 591 处，而且它是单向的。** 回退是一次同样规模的第二次重写，而这
  正是这份推理被记录在这里、而不是记录在一条提交消息里的原因。上面那次纠正随后又花掉了 327 处
  —— 那是支持这句话的证据，不是反对它的。
- **标记不用帮忙就渲染成彩色。** `🔨`（U+1F528）和 `🧭`（U+1F9ED）都是原生表情码点，所以任何
  生成它们的东西都不需要知道变体选择符这回事。
- **标记住在 mermaid 图里面**，不只住在散文和表格里 —— 在 `the-stack/02-network.md`、
  `the-stack/03-compute-and-images.md`、`cross-cutting/kubernetes.md`，以及
  `build-out/README.md` 里那份步骤模板里。一次文本替换会碰到图的源码，所以这些图在更改之后被
  重新校验，而不是被假定完好。
- **`honesty-audit` 按这些标记给声称分类**，所以这个 skill 的更新不晚于它所分类的那些散文。一段
  skill 与语料互相不同意的窗口，会产出自信地错着的审计。
- **中文镜像跟着正本一起变。** `docs/zh/` 声明英文是事实来源；在镜像里不一样的标记，会让那句声称
  恰好在最容易核对的那个地方变成假的。
