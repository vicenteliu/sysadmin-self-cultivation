# Godot 是一个设计期工具，而楼面只保留一套色板

> 🌐 **语言：** [English（默认）](../../../../docs/adr/0013-godot-is-a-design-tool-and-the-floor-keeps-one-palette.md) · **中文**
>
> ⚠️ 本项目**默认语言为英文**，`docs/adr/0013-godot-is-a-design-tool-and-the-floor-keeps-one-palette.md` 是"事实来源"。本页中文是多语言支持的一部分，可能略滞后于英文版；两者不一致时以英文为准。

[楼面](0011-the-floor-renders-the-reference-office-and-may-not-compute-it.md)是一个二维游戏场景，
而建一个游戏场景的显而易见的方式是一个游戏引擎。Godot 有一个瓦片编辑器、一棵场景树和一个 HTML5
导出；在 JavaScript 坐标里手工排一间一百一十个端口的办公室，并不明显是更好的计划。

但 [ADR-0006](0006-the-viewer-vendors-its-dependencies.md) 已经为 viewer 打过这一仗，并且是靠一条
具体的需求赢的：**那条直接路径是一条命令、什么都不用装**，而且它在飞机上也能用。它否决的四个选项
里有两个，是因为它们是换了名字的安装步骤而被否决的。

## 决定

**Godot 永远不会抵达浏览器。它是一个设计期工具，而它的输出是数据。**

场景在 Godot 里排布，而离开它的是一份瓦片摆放、物体位置和可按拍寻址的镜头目标的 JSON，外加精灵图
集。`site/` 里那个运行时是手写的 Canvas2D，而且它不知道 Godot 存在 —— 和 `build-diagrams.py` 是
同一个形状，那个脚本把一份创作出来的源变成一件被提交的产物，而 viewer 不需要任何工具链就能消费它。

**美术一半是画的、一半是生成的。** 场景 —— 地板、墙、家具、机柜 —— 是创作出来的位图像素画，因为
程序化绘制有一个看得见的天花板，而借用这种形式的意义就在于它看起来像一个**地方**，而不像一张图。
那群**人**是从一小组零件在代码里生成的，因为六十五个人形需要变化，而没有人打算画六十五遍。这就是
这种形式已有的那个范例所到达的那个分工，而它值得抄，不值得重新发现一遍。

**楼面只有一套色板，而且不跟随读者的主题。** viewer 渲染的其他一切都会随主题开关切换：mermaid
重新渲染，hero 图在派生出来的浅色和暗色变体之间切换，遵循 `sysadmin-brass.profile.md` 里明说的
一条机械反转规则。那条规则之所以行得通，是因为那些产物是文本。位图像素画不是，而遵从那个开关会
意味着两套手绘精灵图集，外加一个让它们保持同步的 `--check`。**一个游戏场景有它自己的光。** 那套
色板取自那层黄铜皮肤，所以它属于这个仓库，而它是固定的。

**产出楼面的一切都被提交** —— 那个 Godot 工程、那些精灵源、那个导出脚本，以及它的输出 ——
并配一个 `--check`，在输出落后于它的源时报告出来。ADR-0007 为那些图定下了这一点，甚至连那份样式
profile 本身都提交了，理由是：一份克隆必须能重建它所看得见的东西。

## 考虑过的选项

- **把 Godot 的 HTML5/WASM 导出当成运行时交付出去。** 因为四条理由被否决，任何一条都够了。那个引擎
  的二进制块比 ADR-0006 需要一整份决策记录去论证的那 2.5 MB 包大一个数量级，而那个包买到的是全文
  搜索 —— 这里没有任何东西买到那么多。编辑楼面会需要 Godot 编辑器，而那正是 ADR-0006 拒绝过两次的
  安装步骤。`serve.py` 是 `http.server`，不发送跨源隔离头，所以那个多线程导出会需要在两条服务路径
  上都动工。而场景的源会变成 `.tscn` 和 `.gd`，那是没法在一份 diff 里评审的 —— 恰好是 ADR-0007
  偏好 mermaid 的那个理由的反面，即*源码和那张图是同一个对象*。

- **全部手工摆放，完全不用 Godot。** 作为虚假的节省被否决。瓦片排布正是一个瓦片编辑器存在的意义，
  而另一个选项是让一个看不见自己在打什么的人，把坐标敲进一个 JSON 文件里。

- **完全程序化的美术，连场景也算。** 这个决定最初就是这个版本，而它在那群人身上活了下来。对场景
  被否决，因为那个天花板是真实且可见的：生成出来的家具读起来像一张屋子的示意图，而不像一间屋子，
  而借用这种形式恰恰就是为了那个差别。

- **两套精灵图集，一套一个主题。** 按成本对收益被否决。它让每一次美术改动翻倍、需要一个没人写过
  的守卫，而买到的是与一个游戏场景没有理由去遵从的开关的一致性。

- **不提交 Godot 工程；只保留那份导出。** 按 ADR-0007 拒绝一份手写暗色变体的同一个理由被否决：
  它让那份布局变成一扇单向门。第一次导出之后，挪一堵墙的唯一办法就是手工去编辑 JSON。

## 后果

- **`site/README.md` 那一行关于主题的说明变错了，必须修订。** 它当前说主题跟随系统设置、mermaid
  会重新渲染、hero 图会切换变体。楼面是这里第一样退出这件事的东西，而 README 应该把这件事说出来，
  而不是让一位读者自己发现。
- **这个仓库长出了二进制美术。** 精灵图集相对那个 vendored 包不算大，但它们是第一批没法做 diff 的
  被提交资产。把一次美术改动当成它自己的一次提交，就像 ADR-0006 对那对 vendored 库所要求的那样。
- **要改布局就必须装 Godot，而那是可以接受的**，恰恰因为**读**或者**跑**任何东西都从来不需要它。
  那份零安装承诺关乎的是读者，而读者不受影响。
- **第一集根本没用 Godot，而这份 ADR 在这一点上并没有错。** 四十八乘三十的瓦片、七间屋子和十二个
  工位组，敲出来比为它立起一条工具链更快，所以 `01-the-network.floor.json` 是被直接创作出来的，
  而 `tools/floor/` 里没有任何 Godot 工程。这个决定所修的是那条**边界** —— 设计期可以，交付出去
  绝不可以 —— 而那条边界不管那个工具有没有被伸手去够，都是有约束力的。
  [`tools/floor/README.md`](../../../../tools/floor/README.md) 平白地说它没有被用过，因为把一份
  计划描述成一个事实，正是这个仓库那些标记存在去抓住的那个失败。
- **场景是以文本创作、派生成位图的，而这是一句比这份 ADR 最初所做的更小的声称。** `tiles.tiles`
  是一个字符一个像素地画出来的，而 `build-tiles.py` 吐出那个 PNG。观感是这个决定想要的那种手绘感；
  存储是可 diff 的，而这个决定当初假定它不可能是。那句"第一批没法做 diff 的被提交资产"结果并不
  适用 —— 那份派生出来的图集被提交了，但它的源是文本，而且是可评审的。
- **那群生成出来的人是最可能让人失望的那部分。** 如果六十五个由零件搭起来的人形读起来很重复，
  回退方案是少数几个画出来的人形加上重新上色的变体 —— 而那改变的是美术流水线，不改变它之上的任何
  一个决定。
