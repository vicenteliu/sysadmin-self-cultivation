# 参考办公室消费服务，并且不运营任何服务

> 🌐 **语言：** [English（默认）](../../../../docs/adr/0015-the-reference-office-consumes-services-and-operates-none.md) · **中文**
>

有人要求 [`the-reference-office.md`](../../the-reference-office.md) 长出三个新的参数域：一台自建
VM 宿主、一朵云的估算面，以及一个在线服务。其中两个取决于一个这个文件从来没回答过、而且从来没
注意到自己没在回答的问题 —— **这间办公室为它外面的任何人跑任何东西吗？**

这个问题不是闲问，因为这个仓库已经持有一个产品侧所需要的那些材料。
[`cross-cutting/ci-cd.md`](../../cross-cutting/ci-cd.md)、
[`kubernetes.md`](../../cross-cutting/kubernetes.md)、
[`databases.md`](../../cross-cutting/databases.md) 和
[`web-and-tls.md`](../../cross-cutting/web-and-tls.md) 都写好了，而且都有用。一位读完那四篇之后
才遇到参考办公室的读者，会合理地问：为什么这间办公室从来不碰它们中的任何一个。

那个答案一直坐在 build-out 里，没被说出来。它那十六步是上行、建筑、身份、设备、网络、租户与邮件、
文件、终端安全、备份、远程访问、资产、会议室、服务台、合规，以及入转离。**没有一步向任何客户交付
任何东西。** 而有两步早就决定了那些工作负载去了哪边：

> | 那个房间装什么 | 服务器、存储、磁带、UPS | 交换机、一台门禁控制器、一台打印设备、一点实验室器材 |
>
> **这里面有多少是 AI：没有。** 这里的变化是工作负载离开了这栋楼 —— SaaS 化和托管，不是模型。
> —— [`build-out/02`](../../build-out/02-the-building.md)

> | 镜像住在哪 | 在场内，在你的基础设施上 | 一份配置 profile 和一份应用清单；那个"镜像"基本是 OS 厂商的 |
> —— [`build-out/04`](../../build-out/04-devices-and-images.md)

## 决定

**参考办公室是一家百人公司的 IT 部门。它消费服务，并且不运营任何服务。** 没有产品、没有客户流量、
没有它要为之负责的公网端点。当这间办公室出现在一个句子里时，那个被跑起来的东西，是**为楼里那
一百个人**跑的。

**它的参数可以持有什么：** 它买什么、买多少个席位、身份住在哪、终端是什么以及它们怎么被替换、
什么会到达服务台、有哪些数据存在以及丢掉它们的代价是什么，以及什么**因为离不开**而跑在本地。
消费，以及那片做消费的估算面。

**它们不可以持有什么：** 一个服务的流量、它的发布节奏、它的错误预算、它的客户、它的 on-call
轮值，或者任何一个只因为楼外有人依赖它才存在的数字。

**一个产品侧，如果将来真的需要，是一个单独具名的场景** —— 它自己的文件、它自己的参数、它自己的
诚实标记 —— 而不是这一个的一个小节。它不被禁止。它是另一个虚构，而它不能不打招呼就出现在这一个
里面。

**`Where things run` 的云那一半继承这条线。** 它里面的每一条都回答同一个问题：*这个为什么不在
IDF 里？* 一个回答不了那个问题的云参数，描述的是别人的估算面。

## 考虑过的选项

- **让这间办公室运营一个产品。** 那些材料存在，而且它会让那四篇横切笔记第一次变得具体。因为两点
  被否决。它改变这个仓库**关乎**什么 —— 从一个支撑一百名员工的 IT 部门，变成一家跑一个服务的公司
  —— 而它会在一张参数表里做这件事，任何地方都没有一份决策记录。而且它会取材的那四篇笔记全都标着
  `mixed`，而这间办公室已有的那些推导是 🔨；这个仓库那片亲手做过的地面唯一具体的地方，会变成它
  最薄的地方。

- **什么都不说，逐参数去决定。** 现状，而且这正是已经在发生的事：在有人问这间办公室运营不运营任何
  东西之前，就有三个域被提议给它了。按 [ADR-0008](0008-a-count-is-not-a-bound.md) 的教训被否决，
  而那恰好是同一个形状 —— 一条只住在散文里的边界会在没人注意到的情况下被越过，因为没有任何东西在
  检查它。

- **保持一个文件，把它拆成一个办公室半边和一个产品半边。** 被否决，因为这个仓库已经在承担两间没有
  名字的百人办公室的代价：有三个 lab 说*一间百人办公室*并自己发明了数字，而它们没有一个引用
  `the-reference-office.md`。在那个本该了结这件事的文件**里面**再加一个虚构，方向是反的。

- **把产品侧放进 `platforms/`。** 被否决，因为那些目录横跨七片面去教一个平台；它们不是场景，而
  一个被丢进其中的场景会被读成一句关于那个平台的声称。

## 后果

- **`Where things run` 的云那一半和本地那一半是互相对照定义的**，这也是为什么它们是一个 ⏳ 小节
  而不是两个。一侧的每一行之所以存在，是因为另一侧满足不了的某个理由。
- **`ci-cd.md`、`kubernetes.md`、`databases.md` 和 `web-and-tls.md` 拿不到一个办公室锚点，而那不
  是一个缺口。** 它们在它们自己的高度上教。一位来找参考办公室在哪儿用到它们的读者，会找到这份记录
  作为替代。
- **一个未来的产品场景从这里开始。** 写它的那个人继承了一个已经说清了它绝不能做什么的决定：
  作为这间办公室的一个小节出现。
- **`Where things run` 一节在有什么东西来要之前保持 ⏳。** 这个仓库里还没有任何东西被迫去发明这间
  办公室的云数字 —— 那四个锚在*一间百人办公室*上的 lab 是服务台、资产对账、权限蔓延和邮件认证，
  而它们没有一个是关于云的。这一节带着它的进入条件、不带内容，就像 `Reference build` 自写下来
  以来一直那样。
