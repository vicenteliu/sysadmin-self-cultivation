# build-out 是一条穿过各条轴的路线，不是第七条轴

> 🌐 **语言：** [English（默认）](../../../../docs/adr/0001-the-build-out-is-a-route-not-a-seventh-axis.md) · **中文**
>
> ⚠️ 本项目**默认语言为英文**，`docs/adr/0001-the-build-out-is-a-route-not-a-seventh-axis.md` 是"事实来源"。本页中文是多语言支持的一部分，可能略滞后于英文版；两者不一致时以英文为准。

---

这个仓库在一批材料之上有六条轴，而 README 说清了它们是干什么的：*"从最贴你问题的那条进。"*
那在你已经知道该问什么的时候管用。它对不知道的那位读者失效 —— 那位要为一间新办公室把 IT 立起来、
而还不知道身份必须在第一台笔记本被纳管之前就定下来的读者。

`build-out/` 通过端到端地走一个场景来回答那位读者：一间百人办公室，单站点外加一个小分支，
被迫混合（有几样东西必须留在本地），带着一份客户驱动的 SOC 2 义务。

## 决定

**build-out 承载顺序与依赖。它不承载内容。**

每一步点名它产出什么、在它开始之前什么必须为真、什么依赖它，然后**指进已有的各条轴**去取实质
内容。一个发现自己在解释 SCIM 怎么工作的步骤已经失败了 —— 那份解释已经存在，而它的第二份拷贝是
第二样要去维持为真的东西。

## 考虑过的选项

- **做成第七条轴。** 否决。这六条是*材料的各个面* —— 按平台、按层、按主题。一次 build-out 不是
  另一个面；它是**一条横穿全部六条的路**。把它归为同侪，会告诉读者还有第七批材料要读，而实际上
  它不教任何新页面。

- **一份独立的、完整写出来的教程。** 否决，而这一个才是真正诱人的：它孤立地读起来更好。但它把
  几乎所有已经写好的东西复制了一遍，而同一份知识的两份手工维护的拷贝，从第一次只落在一边的编辑
  起就开始分岔。那个失败是静默的 —— 那份更新的拷贝看起来和更旧的一样权威。

## 后果

- **一个步骤按构造就是短的。** 如果一个步骤很长，那它在解释某样属于某条轴的东西；把它挪过去并
  链接。
- **覆盖率变得可度量。** 每一步都应该能指向一个可跑的 lab 或一个 `toolbox/` 工具。那些指不出来
  的被记录在 `build-out/GAPS.md` 里 —— 而那份清单比一份路线图更像路线图，因为它是从一个真实场景
  派生出来的，而不是从一种"缺了什么"的感觉。一个缺口只有在这一步**本应**有一个工具、而仓库没有
  的时候才是一个缺口；一间百人办公室从不碰的材料不是一个洞。
- **诚实标记在这里比在别处更难糊弄。** 一段绿地叙事会诱使你用和你做过的那些部分同样自信的声音，
  去写你没做过的那些部分。步骤 0–2（租约、上行、竖井与 IDF）基本在亲手经验之外，并且是被写成
  *签字之前该问的问题*，而不是写成怎么谈判 —— 一份问题清单可以从第一性原理推出来，谈判不行。
