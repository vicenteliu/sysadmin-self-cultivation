# 楼面渲染参考办公室，而且不许计算它

> 🌐 **语言：** [English（默认）](../../../../docs/adr/0011-the-floor-renders-the-reference-office-and-may-not-compute-it.md) · **中文**
>
> ⚠️ 本项目**默认语言为英文**，`docs/adr/0011-the-floor-renders-the-reference-office-and-may-not-compute-it.md` 是"事实来源"。本页中文是多语言支持的一部分，可能略滞后于英文版；两者不一致时以英文为准。

viewer 正在长出一个**楼面**：[参考办公室](../../the-reference-office.md)的一个可交互二维场景，
带平移和缩放、可点的物体，以及一群坐在工位上的人形。一篇
[走读](0009-the-walkthrough-ships-its-script-not-its-audio.md)在它上面播放。

[ADR-0005](0005-the-site-is-a-view-not-a-seventh-axis.md) 定下了这个站点渲染材料、并且不添加任何
材料，并给出了那个测试：*如果删掉 `site/` 会让这个仓库损失一个事实，那条边界就已经被越过了。*
一个 Markdown 渲染器不可能意外地越过那条线。一个模拟器可以在一个下午之内越过它，因为一个知道六个
接入点在哪的场景，离"告诉你十六个该放在哪"只差一个很小的函数。

## 决定

**楼面是一个视图。它渲染 Markdown 已经陈述的事实，并且不计算任何东西。**

**那群人就是那份负载，不是装饰。** `the-reference-office.md` 陈述了那条占用曲线 —— 星期二大约
六十五、星期一五十出头、星期五三十来 —— 并从中推导出大约一百四十五台关联设备，而那是接入点数量的
输入。楼面上那些人形**就是**那个数字，所以"一间百人办公室的行为像一间六十五人办公室"这个论证是
可以看的，而不是被断言的。**这就是渲染：屏幕上的每一个数量都是从一份文档里读出来的，绝不是被
场景算出来的。** 把人头数设成四百、然后让楼面吐出一个接入点数量，那这个 viewer 就刚刚变成了一个
事实第一次出现的地方。

**缩放是语义的，分三档，因为这些材料有三档。** 远处是占用、覆盖和那四个网段（🔨）。中间是布点 ——
那间大屋子挣到一个专属射频、会议室系统走铜线、电话亭单独计数（**🧭**，也是叙述者切换立足点的那一
档）。近处是那条路径：三台接入交换机、大约一百一十个活跃端口、接近五百瓦的 PoE 预算，以及被画成
三种不同线缆的三个速度层（🔨）。*上联和堆叠才是尺寸错误住的地方*是一句关于"你凑近看会看到什么"的
声称，而那正是语义缩放的用处。

**一个物体的面板展示那份判断和那些判据，绝不展示一份配置。** 点一个接入点，会给出它为什么在那儿、
那个数量是怎么得出来的 —— 按客户端数是三、按吞吐是一、按覆盖下限是四、布点之后是五或六，而绑定
它的是覆盖 —— 它对交换机要求什么，以及那些锚点，而那些锚点在它们所链向的标题里携带各自的 🔨/🧭
标记。它不给出一条 SSID 到 VLAN 的绑定，也不给出一段 802.1X 配置。这个仓库不持有任何设备配置，
`the-reference-office.md` 的 `Reference build` 仍然是 ⏳ 并带着一个明说的进入条件，而一个面板不是
去触发它的理由。**如果需要配置，它们先被写进那一节 —— 带日期、可整体替换、通过 ADR-0002 那个
"有人能照着这个去买吗"的测试 —— 然后那个面板再链向它们。**

**物体的身份和锚点绑定住在这条路线里，不住在 viewer 里。** 它们坐在
`walkthrough/<episode>.floor.json` 里，就在稿子旁边。*有六个接入点，而其中一个属于那间大屋子*
是一个事实；一个只在 `site/` 底下持有的事实过不了 ADR-0005 的删除测试。

**浏览是默认模式；叙述是压在它上面的一层。** 一位没有配置 TTS 的读者打开的是一个他可以探索的
楼面，而不是一个等着音频的播放器。播放期间点击会暂停叙述，因为两股同时到来的信息会互相抵消而不是
叠加。

## 考虑过的选项

- **一群装饰性的人。** 工位上有人形只为气氛，什么都不携带。否决：那是一块压在文档上的屏保，而且
  它会让这个仓库最反直觉的那条发现 —— *为星期二定尺寸，不为工资名册* —— 和现在一样地不可见。
  建一个楼面的全部理由，就是这句声称关乎的是一间屋子里的身体。

- **一个可参数化的模拟器。** 人头数、楼面面积和设备比例的滑块，把那些推导实时接起来。听起来最有用
  的那个选项，也是最该狠狠拒绝的那一个：它会真的很好，而它会把这个仓库的算术放进 `site/` 底下的
  JavaScript 里，在那儿没有评审者、没有镜像、也没有任何 `--check` 会看到它。如果那些推导应该是
  可执行的，它们属于 [`toolbox/`](../../toolbox/README.md)，作为一个带 `Tested on:` 行的工具，
  而不属于一个 viewer。

- **物体面板里的配置片段。** 否决，而这是那个有真实代价的否决 —— 点一个接入点得到的是散文和链接，
  而不是可以拷走的东西，而那正是"无聊"这个词一开始的一部分含义。还是这么定了，因为一份配置的半
  衰期比一个型号还短，而且它会悄悄把这个仓库所声明的高度搬进一个没被评审过的 JSON 文件里。经由
  `the-reference-office.md` 的那条路仍然敞着。

- **把物体绑定当作 `site/assets/` 下的 viewer 资产。** 建起来更简单，而在 ADR-0005 的测试上是错的。
  删掉 `site/` 会把这间办公室的清册一起带走。

## 后果

- **`the-reference-office.md` 现在为某样被渲染的东西承重了。** 它的数字出现在一块屏幕上，所以对
  它们的一次更改会改变一张图。那是有意为之的耦合，而且它只往一个方向跑：文档决定，楼面跟随。
- **楼面回答不了"那我的办公室呢？"，而它会被问到。** 那个诚实的答案就是这份文档已经给出的那个 ——
  *那些推导才是可迁移的部分* —— 而楼面应该指向它们，而不是长出一块设置面板。
- **一个 `--check` 守住它守得住的东西。** 一个 `.floor.json` 里的每一个物体 id 都必须解析到一个
  `sources:` 文件里一个存在的锚点，而它引用的每一个 beat id 都必须在稿子里存在。两个检查都没法
  判断屏幕上一个数字是不是文档里那个数字；那仍然靠人去读 —— 就是
  [ADR-0008](0008-a-count-is-not-a-bound.md) 不得不做出的那份承认。
- **三种受众，三件完整的产物。** 稿子在 GitHub 上读起来完整、楼面在静音下浏览起来完整、音频在没有
  屏幕时听起来完整。任何只在三者同时在场时才成立的功能，都是一个让多数读者失败的功能。
