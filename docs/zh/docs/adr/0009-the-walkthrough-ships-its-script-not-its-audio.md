# 走读交付它的稿子，不交付它的音频

> 🌐 **语言：** [English（默认）](../../../../docs/adr/0009-the-walkthrough-ships-its-script-not-its-audio.md) · **中文**
>
> ⚠️ 本项目**默认语言为英文**，`docs/adr/0009-the-walkthrough-ships-its-script-not-its-audio.md` 是"事实来源"。本页中文是多语言支持的一部分，可能略滞后于英文版；两者不一致时以英文为准。

[`walkthrough/`](../../walkthrough/README.md) 是对[参考办公室](../../the-reference-office.md)的
一次叙述式走过：一层百人楼面，按顺序讲，用一种这个仓库其余部分刻意不用的语域。它是这里第一份写来
**被机器念、被人听**的材料，也是第一份有仓库之外发布渠道的材料 —— 一个播客源。

有两个问题跟着它一起来了，而两个都没有自己回答自己。一个故事是不是一条新的轴？以及那些音频住在哪？

## 决定

**走读是一条路线，而这个仓库只交付稿子。**

**一条路线，不是一条轴。** 和 [ADR-0001](0001-the-build-out-is-a-route-not-a-seventh-axis.md)
以及 [ADR-0005](0005-the-site-is-a-view-not-a-seventh-axis.md) 同一个测试：*它教不教一个新页面？*
它不教。第一篇走读里的每一个事实，都已经坐在 `the-reference-office.md`、
`cross-cutting/site-network-design.md` 或者 `build-out/05-network.md` 里。它加的是一个**顺序**和
一种**语域**。它的序列尽管如此仍然是它自己的 —— 第一篇走读横跨两条轴上的三个文件外加根目录 ——
所以它不是 `build-out/` 那十六步配了个声音，而且编号也不对应。

**稿子是一等文档；音频不在这棵树里。** 一个 `walkthrough/*.md` 和这里别的一切一样是带 front
matter 的 Markdown：GitHub 渲染它、`docs/index.json` 记录它、搜索语料装着它、一个 `--check` 能抓住
它变陈旧。音频是生成的 —— 由一位带着自己 TTS 凭据的读者，或者由作者为发布而生成 —— 而没有任何录音
被提交。

**这个文件只包含那些会被念出来的词。** 没有表格、没有内联链接、没有*如上表所示*、没有括号里的
旁白；数字按人说的方式写。交叉引用住在 front matter 的 `sources:` 里。这是把
[ADR-0007](0007-a-figures-medium-is-decided-by-what-renders-it.md) 的论证复用了一遍 ——
*源码和产物是同一个对象，所以它们不可能互相不一致*。`cat` 一下这个文件，你手上就是 TTS 的输入，
中间没有一个会漂移的抽取步骤。

**一篇被发布的走读会冻结。** 它的 front matter 带着 `published:` 以及每一个 `sources:` 文件在那
一天的指纹。在那之后这个稿子不被编辑：一个错误变成一条被记录在文档里的**勘误** —— *音频里说了 X；
X 是错的* —— 因为一段在播客托管上的录音改不了，而一次静默的修复会让它对每一位听众继续撒谎。
一个检查器会报告一个源在一篇已发布的走读底下挪动了，而那是"一集需要重录"的唯一可靠信号。

## 考虑过的选项

- **把已有的散文念出来。** 最整齐的答案：没有新词、没有新的文件种类、ADR-0005 不被触动。因为它
  听起来是什么样而被否决。这个仓库的散文刻意是简短的、陈述式的、表格很多的 —— 一个值得保留的编辑
  选择 —— 而一个语音引擎把它念出来会产出一场讲座，而那恰恰是走读存在去不成为的那一样东西。语域
  才是那个交付物，而语域熬不过"把一份为眼睛而写的文档念出来"。

- **做成第七条轴。** 按 ADR-0001 的测试被否决，而它明明白白地没通过：第一篇走读没有教任何一个
  这个仓库还没有的事实。把它归为一条轴，还会强迫它在这些材料上做到完备，而它明确不是 —— 它一次
  长一集，需求优先，像 `toolbox/` 那样。

- **一个单独的仓库，或者一个桌面应用。** 确实诱人，因为那个楼面是一个游戏场景，而一个游戏引擎会
  很自在。被否决，是因为材料会**分叉**，而那个分叉会是人们真正在看的那份拷贝 —— 就是 ADR-0001 和
  ADR-0005 已经各自否决过一次的那个失败。一个卫星拿不到 front matter、在检索索引里没有位置、没有
  镜像，也没有任何东西在它变陈旧时抓住它。

- **把音频提交进来。** 因为两点被否决。那种大小的二进制产物会让
  [ADR-0006](0006-the-viewer-vendors-its-dependencies.md) 不得不去论证的那个 vendored 包都相形
  见绌，而且**它们对多数读者本来就是错的**：一位听众自己的 TTS 声音、语言和语速都和作者不一样，
  所以一段被提交的录音服务一个人，并为其余所有人把这棵树撑肿。

## 后果

- **三件产物必须各自站得住，因为三种受众各自缺一样东西。** 一位 GitHub 读者没有图也没有声音。
  一位 viewer 用户可能没有声音。一位播客听众**没有任何屏幕** —— 而那是决定最多的那条约束，也是
  在盯着一块屏幕时最容易忘掉的那一条。稿子必须读起来完整、楼面必须浏览起来完整、音频必须听起来
  完整。
- **诚实标记必须被念出来。** 一个画在楼面上的 🔨/🧭 徽章在播客频道上并不存在，所以走读的叙述者
  在立足点变化时，用故事自己的口吻把那条边界说出口。在第一集里它变一次，从 🔨 的分段与地址规划
  材料，转到 `the-reference-office.md` 已经标明是来自厂商工程指南、而不是来自跟一次部署一起生活
  过的 🧭 无线算术。
- **`site/README.md` 和 `ROADMAP.md` 获得了一样新的要去描述的东西**，而 `CONTENTS.md` 获得了一条
  新的路线。走读不在轴列表里，也不拿一张卡片 —— 就是 ADR-0005 让 `build-out/` 不拿一张时给出的
  那个理由。
- **那门勘误纪律第一次被用的时候会显得很奇怪。** 把一个已知错误留在文档里、旁边配一条注释，读起来
  像是马虎 —— 直到你想起那段录音改不了。这和 `docs/questions.md` 拒绝删掉一条已答条目时用的是
  同一份推理。
