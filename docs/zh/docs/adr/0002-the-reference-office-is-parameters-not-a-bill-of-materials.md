# 参考办公室是参数，而那些型号名被隔离了

> 🌐 **语言：** [English（默认）](../../../../docs/adr/0002-the-reference-office-is-parameters-not-a-bill-of-materials.md) · **中文**
>
> ⚠️ 本项目**默认语言为英文**，`docs/adr/0002-the-reference-office-is-parameters-not-a-bill-of-materials.md` 是"事实来源"。本页中文是多语言支持的一部分，可能略滞后于英文版；两者不一致时以英文为准。

每一个 build-out 步骤都说*一百个人*，却从没说过这个地方有多大，于是一个教决策的仓库没有任何具体
的东西可以对着做决定。`the-reference-office.md` 在根一级修掉这件事，就放在
`00-the-operating-model.md` 旁边，因为它是整个仓库的一个前提，而不是任何单一步骤的产物。

它携带型号名和成本形状，而这个仓库从来没这么做过。那才是值得解释的那部分。

## 实际被决定的是什么

**各小节是按保质期分开的，不是按话题。** 推导、判据、型号名和成本，老化的速度差得离谱。混在一起，
腐烂最快的那部分会把其余的一起拖下去。分开放，那张有日期的表可以在两年后被整体替换，而不用碰一行
解释这些数字为什么是这些数字的散文。

**允许出现型号名，在一张被隔离的、带日期的表里。** 它们挣得了自己的位置，因为这个仓库是一份教程
而做过的实例能教人；它们被隔离，因为它们是这些材料里唯一半衰期只有两年的部分，也是唯一能让一个
教学仓库读起来像一份采购指南的部分。

**那个 reference build 有一个机械的准入测试 —— 有人能照着这个去买吗？** 型号、端口数、接入点数
都通过。一个协议怎么行为则不通过。没有那个测试，这个文件会随时间一句一句地、每一句都看起来很合理
地向下漂进机制里，而这个仓库会悄悄地不再是它所说的那个东西。

**它在场景需要一个参数时生长，绝不在一段视频需要一个参数时生长。** 那个测试是：如果什么都不曾被
拍摄，这个场景还会不会想要这一行。为服务一次录制而存在的内容，属于那次录制。

**面试材料是问题加上每一个所探的东西，绝不是写完的答案。**

> 只取代这第五条决定；这一页上另外四条仍然成立。答案现在被写了出来，它们的形状由那一节的诚实

## 两件刻意没做的事

**`build-out/GAPS.md` 里那条建筑侧的边界原样保留，没被碰。** 它写的是：把一个毛坯建成机房是与
承包商一起完成的物理工作，而建筑那一侧仍然是一段拉伸。那条边界关乎*去做那份工作*。这个文件关乎
*那个场景的参数*，那是另一回事，所以参考办公室住在根目录，而不住在步骤 02 里面。
**没有任何东西被取代，也没有任何东西需要被取代。**

**仓库里已有的东西没有一样被重写进它。** 故障模式已经住在全部十六步的 `Getting it backwards`
一节里，可跑的工具已经住在 `toolbox/` 里，而与 AI 协作已经住在 `ai-workflow/` 里。参考办公室指向
这三处，一处都不复制。同一批材料的两份平行拷贝会漂移，而那次漂移是静默的。

## 那个刻意做得很薄的第一版

只有参数和推导被写了出来。Selection rules、reference build、成本形状和面试材料都是带着进入条件的
桩。

设备选型依赖那些参数，而不是反过来 —— 你没法在知道这层楼之前就给接入点定数量。因为一集网络的
内容恰好在制作中就先写网络设备，恰恰就是上面那条生长规则存在去防止的那种耦合。
