> [README](README.md) 是 *GCP 是什么*；[architecture](architecture.md) 是*它怎么组织*；
> 这篇笔记是**跑它实际长什么样** —— 那份运维简报、凌晨三点什么会把你叫醒、按节奏拆开的真实运维活，
> 以及 AI 怎么在那条运营循环里挣到它的位置（和那条[学习 ramp](ai-ramp.md) 不同）。

## 那份简报 —— "运维 GCP"意味着什么

在本地，运维意味着手放在硬件上。在 GCP 上硬件没了，而这份工作往上挪：**你通过声明意图来运维，
看着平台拿它做了什么，并让结果保持安全、可靠、负担得起。** 定义 day-2 工作的那三个问题：

- **它健康吗？** —— 而且你会在一位用户告诉你之前知道吗？（可观测性 —— 而 GCP 那套原生 SLO 让这
  成为一个一等问题）
- **它安全吗？** —— 最小权限还守着吗、没有东西暴露在外、没有在错误的层级上做绑定吗？
- **它负担得起吗？** —— 没有被遗忘的资源在计费、没有工作负载挂在错误的定价模型上、没有出网意外吗？

下面的一切都是这三个问题，被落到实处。

## 运维笔记 —— 在 GCP 上什么会把你叫醒（以及什么应该）

那些真正产生故障的故障模式，大部分在那条[共担责任线](architecture.md)的客户那一侧：

- **那个公开的 Cloud Storage 桶** —— 私有数据被一次配置错误弄成了公开；那次典范式的云上入侵。
  统一的桶级访问，加上一条有人**真的去读**的 Security Command Center 发现
  （[`the-stack/07`](../../the-stack/07-security.md)）。
- **那把泄露的 service account 密钥** —— 一份被提交进仓库、被扫描器找到的 SA 密钥 JSON。这**就是**
  为什么 GCP 推的是挂上去的 service account 和 Workload Identity Federation，而不是密钥文件
  （[`身份`](../../cross-cutting/identity-iam.md)，以及 [`automation.md`](automation.md)）；
  一把在 git 里的密钥就是一次故障。
- **"这个为什么够不到那个？"** —— 那个每日网络故障，带一个 GCP 特有的转折：防火墙规则瞄准的是
  **tag/service account**，而那个**全局 VPC** 默认跨 region 路由，所以那个 AWS 形状的心智模型会
  给出错误答案。[`the-stack/02` 那架调试梯子](../../the-stack/02-network.md)仍然适用 ——
  只是对着 GCP 的模型爬。
- **那份账单意外** —— 出网、跨区域流量，或者一台被遗忘的实例（[`成本`](../../cross-cutting/cost.md)）。
  如果你设过，它以一条**预算告警**把你叫醒；如果没设，它以一张发票把你叫醒。
- **本想要区域级却成了单 zone** —— 一个"高可用"的服务，两个副本都在一个 zone 里，而它是在那次它
  本该熬过的 zone 事件当中被发现的。regional PD / 区域级 MIG 的存在恰恰就是为了防止这个
  （[`the-stack/01`](../../the-stack/01-physical.md)）。
- **一次在错误层级上的 IAM 绑定** —— 一个在 Org 或 Folder 上授予的角色，继承向下流到每一个
  project，而它是在某人拥有他不该有的访问权时被发现的。继承既是力量也是危险
  （[architecture](architecture.md)）。

## 那些运维活，拆开来看

一个 GCP 管理员反复要做的那些活，按**节奏**分解 —— 因为"这份工作到底包含什么"，最好由"你做什么、
多久做一次"来回答：

| 节奏 | 任务 | 面 | 它为什么要紧 |
| --- | --- | --- | --- |
| **持续（自动）** | 对健康、错误率、延迟、预算、安全发现告警；**SLO 燃尽率告警** | 可观测性、成本、安全 | 系统自己看着自己；你是被叫醒，不是被意外。GCP 那套原生 SLO 让这件事很锋利。 |
| **持续（自动）** | Managed Instance Group 自愈/替换不健康的实例；自动扩缩 | 计算 | 牲口，不是宠物 —— 故障是被处理的，不是被守着的。 |
| **每日** | 分诊告警和 Security Command Center 的发现；对真的那些动手 | 安全、可观测性 | 那些发现只有在有人读它并动手时才有用。 |
| **每日** | 回答"X 为什么够不到 Y"和"这是谁干的"（Cloud Audit Logs） | 网络、身份 | 那两个最基本的故障与审计问题。 |
| **每周** | 复审 IAM：每一层级上的绑定、过宽的角色、没用过的 service account | 身份 | 继承来的授予会衰减成过度授权；这就是抓住那次漂移的方式。 |
| **每周** | 成本复审：异常、没打标签/标记的花费、涨得最多的项 | 成本 | 在发票之前抓住那个被遗忘的资源。 |
| **每月** | 从利用率 rightsizing；重新审视承诺用量折扣 / preemptible 的覆盖 | 成本、计算 | 多数实例配得过大，因为没人看过。 |
| **每月** | 刷新自定义镜像；用一个新镜像滚一遍 MIG | 计算、安全 | 关掉已知 CVE 的暴露面；重装优于就地打补丁（[`the-stack/03`](../../the-stack/03-compute-and-images.md)）。 |
| **每季** | 对一份备份做恢复测试；真的核实 RPO/RTO | 存储 | 一份没测过的备份是一个希望（[`the-stack/04`](../../the-stack/04-storage.md)）。 |
| **每季** | 访问再认证；复审 Org Policy 约束和层级护栏 | 身份、安全 | 证明那些护栏还守着；审计要证据。 |
| **有故障时** | 检测 → 遏制 → 根除 → 恢复 → 写那份复盘 | 全部 | 这整个仓库所关乎的那份判断；凌晨三点的那份镇定。 |
| **有变更时** | 一切走 IaC 加评审，不走控制台 | 发放 | 控制台是用来看的；变更走代码（[`iac`](../../cross-cutting/iac-and-config.md)）。 |

这张表让两件事变得可见。第一，**多数例行工作是自动的、或者本该是自动的** —— 人的活是分诊、复审和
判断，不是杂活。第二，**那个复审节奏（每周 IAM、每周成本、每季恢复）是团队会跳过、然后后悔的那
部分** —— 它不光鲜，而它恰恰是继承来的过度授权、超支和恢复不出来的备份藏身的地方，直到它们变成
故障。

## AI 怎么协助运维工作（不只是学习）

[ai-ramp](ai-ramp.md) 那篇笔记讲的是*快速走到胜任*；这一节讲的是在你已经懂 GCP 之后，AI 在*日常
运营循环*里的位置。不同的活，同一门纪律：**AI 提供速度，判断提供真相。**

```mermaid
flowchart LR
  signal["一个信号：告警 日志 被拒请求 账单尖峰 报错"] --> ai["AI：解释 关联 起草那个修复或那条查询"]
  ai --> you["你：对着现实核实 决定 担起那个判断"]
  you --> act["动手：经 IaC 施加 跑那条命令 关闭那次故障"]
  act -.->|"下一个信号"| signal
```

AI 在运维里真正挣到饭钱的地方：

- **故障副驾 / 橡皮鸭** —— 把那条审计日志条目、那次被拒绝的请求、那条 `gcloud` 报错、那段栈回溯
  贴进去：*"这是什么意思，你接下来会查什么？"* AI 在把一个晦涩信号变成一个假设上很快 —— 而你去
  测它。
- **写查询** —— *"一条 Cloud Logging 查询，找出过去一小时里按路径分的 5xx 尖峰"* —— AI 写日志查询
  语言 / BigQuery SQL 很流畅；在你相信那张图之前，拿已知数据去做一次合理性核查。
- **日志与指标分诊** —— 归纳一个吵闹的日志窗口、把相似的错误聚在一起、把异常浮出来 —— 对一堆没人
  想滚动的量做一次很强的初筛。
- **把修复起草成代码** —— *"关掉这条发现的 Terraform / Org Policy / 防火墙规则变更"* —— 一份走
  正常 IaC 闸门的、可评审的初稿，绝不是一次 AI 说服你去做的控制台变更。

在 GCP 的运营循环里 AI **绝不能**被信任的地方 —— 这里的故障模式比在学习里赌注更高，而其中一个是
GCP 特有的：

- **它会在 GCP 上给你 AWS 形状的建议。** 在 AWS 内容偏多的文本上训练出来的 AI，会给一个
  **全局 VPC** 递上**区域级 VPC / peering** 的网络指导，或者对着瞄准 tag/SA 的防火墙规则用
  security group 的思路。每一次都要抓住它 —— 这是最常见的那个 GCP 上的 AI 错误。
- 它会**发明不存在的 `gcloud` 参数、资源名和 API 字段** —— 在跑任何会改变状态的东西之前先核实。
- 它会**起草宽松的修复** —— 一条"为了让它能用"、而宽得离谱的防火墙规则或 IAM 绑定。每一份 AI 起草
  的修复都要手动收紧。
- 它**拥有不了这次故障。** AI 加速那次查找和那份初稿；那个决定、那个爆炸半径判断，以及凌晨三点的
  那份问责，都留给你。

那条让它保持安全的规则：**AI 碰信号和初稿；你碰生产。** 任何 AI 建议的、会改变状态的东西，都走和
你自己的变更同一道评审加 IaC 闸门（[`iac`](../../cross-cutting/iac-and-config.md)）。

## 诚实边界

🧭 **ramp —— GCP 在这里没有任何生产亲手经验，而且它就是这么标的。** 那门运维**纪律**是 🔨 ——
分诊、故障方法、那个复审节奏、最小权限复审、恢复测试、把成本和漂移当成信号 —— 因为它是同一门从
真实基础设施和机队工作里带过来的运维手艺，而在那里传呼是真的会响的。但每一样 GCP 服务的细节
（哪个控制台、哪条发现、哪个 SLO 工具）都是那条 🧭 ramp，按这个仓库的方法测绘并验证过，而**不是**
被声称成为一片生产 GCP 估算面值过班。这里的声称是一份可迁移的运维纪律，加上一条通向 GCP 那套工具
的、快速而诚实的 ramp —— 而上面那条 AI 辅助的运营循环，就是那条 ramp 怎么被施加，而不假装那份判断
是从机器那儿来的。
