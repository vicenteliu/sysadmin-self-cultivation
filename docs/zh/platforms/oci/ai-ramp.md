# OCI —— 那条 AI 辅助 ramp

> 怎么在几天里在 OCI 上走到*胜任* —— 用 AI 当副驾，并且让它保持诚实。OCI 是那套 ramp 方法一个很
> 干净的案例：一个懂另一朵云的管理员已经把那七片面映射过了，所以这份活就是翻译名字，并抓住 Oracle
> 刻意建进去的那几个差别。

[`WHY.md`](../../WHY.md) 的那个前提：一个有经验的管理员加上 AI，能在几天里就在一个从没碰过的平台上
干活。OCI 比多数平台更奖励这一点，因为它是在 AWS/Azure/GCP **之后**被设计出来的，并借用了它们的
形状 —— 所以它有很大一部分是改名，而那条 ramp 基本就是去找那四个不是改名的地方。还是那两门被扣在
一起的纪律：**AI 提供速度，判断提供真相。**

## 那条循环（OCI 口味）

1. **锚定到你已经知道的东西上。** *"我懂 AWS 的账号/VPC/IAM（或者 GCP 的 project）。把 OCI 的
   compartment、VCN、shape 和 IAM policy 映射到那上面 —— 一样的、改了名的，还是真正不同的？"*
   那四个差别几分钟内就浮出来。
2. **先猎那些刻意的差别** —— 把注意力花在这里，别花在那 90% 一模一样的部分上：
   - **Compartment** —— 那个爆炸半径单位（可嵌套；IAM policy 的范围就定在它们上），
     是一个 AWS 账号 / GCP project 的对应物。
   - **OCPU 对 vCPU** —— 一个 OCPU 是一个*完整物理核*；同样的"2 个 CPU"意味着两倍于别处那个超线程
     vCPU 的算力。漏掉这一点，你的尺寸估算和成本对比就差了 2 倍。
   - **Security list 对 NSG** —— 两套重叠的包过滤机制；挑一个并标准化。
   - **那门策略语言** —— 人读得懂的语句（`Allow group … to … in compartment …`），不是 JSON。
     更好，而且不同到需要去学。
3. **拿到那 80/20**、**生成那个产物**（Terraform / `oci` CLI）、**对着当前文档核实**，并
   **在一个 Always Free 层的 tenancy 里跑它** —— OCI 那个免费层让"现实作为评审者"真的是免费的。

## 那些真能挣到饭钱的提示词模式

- **翻译者：** *"在我已经懂 AWS/GCP 对应物的前提下解释 X —— 只讲 OCI 特有的那部分差量。"*
- **异类猎手：** *"在这一点上 OCI 和 AWS 真正不同在哪，以及我的 AWS 直觉会在哪儿给出错误答案？"*
- **最小权限生成器：** *"恰好只做这件事的那条最紧的 OCI 策略语句。"*（然后手动收紧。）

## AI 会烧到你的地方（验得最狠）

- **IAM 策略语句** —— 它会发明动词/资源类型，并把 compartment 的范围搞错；那门人读得懂的语法
  让错误的策略*看起来*是对的。
- **OCPU/vCPU 与定价** —— 它会把 OCI 那个完整核的 OCPU 和超线程 vCPU 混为一谈，并引用过期的价格；
  每一个尺寸/成本数字都要核实。
- **Security list 对 NSG** —— 它会把这两个过滤层搅在一起，就像它在 AWS 上把 NACL 和 SG 搅在一起
  那样。
- **服务名与 CLI 参数** —— OCI 更年轻、在训练数据里被代表得更少，所以 AI 在这里产生的幻觉**比在
  AWS 上更多**，不是更少。验得更狠。

## 为什么这是一项**系统管理员的**技能，而不是一条捷径

AI 能在几秒钟里生成一个 VCN 和一条 compartment policy。它没法告诉你，那台实例上不了网是因为那张
路由表没有网关，或者你那台"2 OCPU"的机器悄悄是你拿来对比的那个成本基准的两倍。它拥有不了那次故障。
那份判断 —— 最小权限的直觉、"这个为什么够不到那个"、读懂那次失败，以及从真实的
[self-host](../../../../platforms/self-host/README.md) 和 [vSphere](../../../../platforms/vsphere/README.md) 工作里来的那份裸金属与故障域
的感觉 —— 才是那门手艺，而它映射到 OCI 上和映射到任何一朵云上一样好。AI 只是把"拥有那份判断"和
"把它施加到 Oracle 那些名字上"之间那些死记硬背移走了。
