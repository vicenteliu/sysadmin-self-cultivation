# Lab —— RAID 买给你的是时间，而重建就是你花掉它的时候

> **输入：** 无 —— 厂商的数字放在文件顶部 · **输出：** 重建窗口、每年丢掉的阵列数、重建中途读错误的
> 概率 · **风险：** 无 —— 不用盘、不用 `mdadm`、不用 root · **root：** 不需要

**目标：** 给[运维篇](../../operations.md)里的一个要点垫上算术：磁盘故障在机队规模上是常态，备件是
消耗品、配一个备件架和一套换盘流程，*RAID 买给你的是换盘的时间；重建期间的第二次故障，是各个 RAID
级别存在要去限定的那个噩梦。* 那句话里每个分句都是一个数字，而这个 drill 从磁盘厂商自己的规格表 ——
年故障率、重建吞吐量、不可恢复读错误率 —— 把每一个算出来。

**你会练到：** 把一个 RAID 级别读成一句关于接下来几小时、而不是关于数据的承诺；按盘容量*加上*换盘
等待时间来衡量窗口；在 RAID 5 和 RAID 6 之间，看着读错误的算术而不是容量的算术来选。

## 这个 lab 为什么是纯本地的

[弧的第三步](../README.md)真的建一个 `md0`，用 `mdadm` 让一个成员失效，读金丝雀，删掉它再读 —— 去
做那件事；两块盘上金丝雀都不见了，是 [`the-stack/04`](../../../../the-stack/04-storage.md) 那条更
老的真理，落到实处。但运维篇里那个要点讲的是*机队*规模和那个*窗口*，而没有一台笔记本有一万个阵列
或者一年。这里，镜像是两个字典，重建是一次除法，窗口是一个概率。不用盘、不用 root、不用
`pip install`。Python 标准库，CI 跑得动它。

## 跑它

```bash
python3 platforms/self-host/labs/raid-buys-time/raid_drill.py
```

退出码 `0` 表示关于这条教训的每一条断言都成立。

## 你会看到什么

1. **一个镜像熬得过一块死盘，并且会把 `rm` 复制过去。** 让一个成员失效：金丝雀读得到。在一个健康的
   镜像上删掉它：一份副本都不剩，因为 RAID 的全部工作就是让一次写到达每一个成员 —— 而 `rm` 就是一次写。

2. **窗口随盘容量变长。** 2 TB 在 150 MB/s 下 3.7 小时重建完；20 TB 要 **37** 小时。大十倍的盘，就是
   对幸存者长十倍的一场赌注。

3. **机队规模把它变成一年一次的事件。** 一万个六盘阵列、2% 年故障率，就是一年 1,200 次重建。有热备盘
   时，每年 **0.51** 个阵列因窗口内的第二次故障丢数据；有备件架时 0.56；盘还在采购路上时 **1.49**。
   换盘等待时间是窗口里更大的那一半。

4. **在今天的盘容量上，RAID 5 的第二次故障是一次读错误。** 一次 20 TB 的重建要从幸存者身上读一百
   TB。按消费级规格每 10¹⁴ 比特一次不可恢复错误算，撞上一次的概率是 **100%**；按企业级的 10¹⁵ 算，
   是抛硬币。就算是 2 TB 的盘，消费级也有 55%。

5. **RAID 6 把它压低一千倍。** 同一个机队、同样的等待时间：RAID 5 每年 1.49 个阵列，RAID 6 是
   0.0015。那个比值就是这个级别存在的意义。

## 验证（别光信这个脚本说的）

```bash
python3 raid_drill.py --break-it raid-is-backup      # exit 1
python3 raid_drill.py --break-it rebuild-is-instant  # exit 1
```

`raid-is-backup` 让 `rm` 只碰你正在看的那个成员 —— *另一份副本还在*的直觉 —— 两条断言倒下，都在第一
步。`rebuild-is-instant` 让换盘不花任何代价：窗口只剩等待时间，重建一个比特都不读，八条断言倒下，因为
第二到第五步里的每一个数字都是那次重建。

然后跟输入吵一架。数字就在文件顶部：

```bash
python3 -c '
import raid_drill as r
for tb in (4, 8, 12, 20):
    print(tb, "TB  RAID 5 URE at 1e-15:", f"{r.p_ure_during_rebuild(tb, r.URE_ENTERPRISE):.0%}",
          " arrays/yr, shelf:", f"{r.fleet_events_per_year(tb, \"stocked shelf\", 5):.2f}")
'
```

把 `AFR` 减半，年发生率减半；把 `REBUILD_MB_S` 翻倍，窗口减半；但你设什么都没法让一百 TB 在 10⁻¹⁴ 下
干干净净地读完，而那就是这个发现。

## 重点

- **RAID 是一句关于接下来几小时的承诺。** 不是关于数据的 —— `rm` 会到达每一个成员 —— 也不是永远的：
  它成立到阵列重新完整为止，而那就是窗口。
- **窗口等于盘容量加换盘等待时间。** 重建你缩短不了多少；等待时间你可以，而[运维篇](../../operations.md)
  那句*备件是消耗品*，就是那个数字，摆在一个架子上。
- **在机队规模上，不太可能就是每年一次。** 一个阵列的 0.1% 是一个机队的一年 1.5 次。这条纪律存在，
  是因为这道算术存在。
- **按读错误的算术来选级别。** 在 20 TB 的盘上，一次 RAID 5 重建是一次预期会失败的重建；RAID 6 是熬
  得过幸存者坏扇区的那个级别。容量的算术从来不会告诉你这一点。
