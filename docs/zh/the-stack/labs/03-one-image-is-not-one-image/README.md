# Lab 03 —— 一个镜像不是一个镜像

> 🌐 **语言：** [English（默认）](../../../../../the-stack/labs/03-one-image-is-not-one-image/README.md) · **中文**
>

> **输入：** 无 · **输出：** 每个引用解析成了什么，以及那两台机器实际差在哪儿 · **风险：** 无 ——
> 不用云、不用 hypervisor、不用凭据 · **root：** 不需要

**目标：** 把[第 03 章](../../03-compute-and-images.md)所建于其上的那道缝变得摸得着 ——
**baked**（在镜像里）对上 **fried**（由 cloud-init 在首次启动时施加）—— 以及那个悄悄把整份可复现性
保证作废掉的词：`latest`。

**你会练到：** 把一个镜像引用当成一次*在构建时被回答的查询*，而不是一个名字；并且在你不得不改一个
值的那一天到来之前，就先决定它属于那道缝的哪一侧。

## 这个 lab 为什么是纯本地的

那一章里的引导式走查会用 Packer 造一个镜像投到 KVM 和一朵云上，再用同一份 user-data 把两边都启动
起来。去做它 —— 它够得到真实的启动失败和一个真实的串口控制台，而那是任何模型都做不到的。但它底下
那个发现是关于一份目录和一个日期的算术，而你没法在一个试用账号上看着六周过去。

不用云、不用 hypervisor、不用凭据、不用 `pip install`。Python 标准库，CI 也跑得了。

## 跑它

```bash
python3 the-stack/labs/03-one-image-is-not-one-image/image_pinning_drill.py
```

exit code `0` 表示关于这个教训的每一条断言都成立。

## 你会看到什么

1. **两台机器，一份写下来的流程，相隔六周。** 两边都写着 `latest`。一台解析成了
   `linux-lts-2401`，另一台是 `linux-lts-2403`。**那条台账记录里没有一列容纳"那个引用解析成了
   什么"**，所以它把它们记成一样的，而它没有撒谎。

2. **它们差在哪儿，以及那属于流水线的哪一半。** 三处差异，*全都是 baked 的*。fried 那一半字节级
   一致，因为 cloud-init 在两边跑的是同一份 user-data —— 而这是这个发现里有用的那一半：你写的那份
   个性化正在精确地做你要求它做的事，而漂移在它下面。

3. **那个只在更新的那台机器上复现的 bug。** *"它在 app-02 上崩，在 app-01 上好好的。"* 同样的角色、
   同样的引用、同样的 user-data，不同的 agent 版本 —— **一次没有人做过的变更，发生在一个没有人挑
   过的日子，没有任何变更记录。** 而为了复现它去重建 app-01，会把 `latest` 再解析一次、把 app-01
   变成 app-02：那份证据一被接触就自我销毁。

4. **把引用钉住，机队就变得可复现。** 两台机器，相隔四十一天，字节级一致。可复现是那个**引用**的
   属性，不是那条流水线的属性。钉住不会拦着你升级；它把升级变成一次提交。

5. **那道缝的代价，用那个决定一个值该住在哪儿的单位来算。** 同一处编辑，代价是*一次重启*或者
   *一次重建加四十次重新部署*，完全取决于那个值被放在了缝的哪一侧。

## 验证（别光信这个脚本说的）

```bash
python3 image_pinning_drill.py --sabotage latest-is-stable  # exit 1
python3 image_pinning_drill.py --sabotage baked-is-free     # exit 1
```

`latest-is-stable` 把运维者脑子里那个模型实现出来 —— 把一个会移动的引用当成一个名字 —— 而三条断言
同时挂掉，因为那三个发现都建在那一个信念之上。`baked-is-free` 把一次 baked 变更按 fried 的价格来
算，那道缝就不再承重了；如果它还能通过，那道缝本来就是装饰。

想再往前一步，往目录里加一条在第 60 天发布的第四个条目，然后为了"复现那个 bug"去重建 app-01。
它会变成第三台机器，和另外两台都不同。不存在一个能收敛的重建次数 —— 这就是钉住那条论据被说成一个
极限的样子。

## 重点

**`latest` 是一次查询，而它在构建时就被回答了。**

三件要带走的事：

- **记录那个引用解析成了什么，而不是它写了什么。** 那份台账从来没有错；它只是没有一列容纳这个
  问题。加一列、在构建时写进去，步骤 3 里那张工单就从一周变成一次两分钟的查询。
- **把慢的和共享的 bake 进去；把逐机器的、或者很可能会变的 fry 出来。** 一个放在错误一侧的值，
  在你需要改它的那天之前都不是 bug，而到那天它是一个项目。
- **一次没有变更记录的漂移仍然是一次变更。** 没有部署过，不是"什么都没动"的证据 —— 它是"动了的
  那样东西不是你部署的"的证据。
