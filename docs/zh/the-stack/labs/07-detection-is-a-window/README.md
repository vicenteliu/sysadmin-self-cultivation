# Lab 07 —— 检测是一个窗口，而有一类发现永不关闭

> 🌐 **语言：** [English（默认）](../../../../../the-stack/labs/07-detection-is-a-window/README.md) · **中文**

> **输入：** 无 · **输出：** 三种机制下逐条发现的暴露分钟数 · **风险：** 无 —— 不用云、
> 不用扫描器、不用凭据 · **root：** 不需要

**目标：** 给[第 07 章](../../07-security.md)那次引导式走查真正在谈的那样东西加上一个单位。一张
控制矩阵给预防和检测各一列，所以它们读起来像两个地位平等的选项。它们不是，而它们的差别在一个没人
写在纸面上的数字里：

```
prevent   exposure = 0 minutes, for exactly the classes the policy names
detect    exposure = (time to notice) + (time to fix), for every class
and one finding does not end when you fix it at all
```

**你会练到：** 汇报暴露分钟数、而不是一个发现计数；以及注意到你的哪一条发现的暴露活得比它的工单
还久。

## 这个 lab 为什么是纯本地的

那一章的引导式走查会把一个真实的 bucket 配错、用原生姿态扫描器逮住它，然后用 policy-as-code 让它
变得不可能。去做它 —— 那个发现面板和那次被拒绝的变更值得亲眼看看。但它底下那个发现是关于引入时刻
和扫描边界的算术，而一片估算面的三十天不是一个试用账号会给你看的东西。

四个普通的错误、三十天、三种机制。不用云、不用扫描器、不用凭据、不用 `pip install`。Python 标准库，
CI 也跑得了。

## 这一篇坐在哪儿，以及它为什么不是第二个 `one-control-three-stages`

[`one-control-three-stages`](../../../cross-cutting/labs/one-control-three-stages/) 问的是一张控制
矩阵**表达不了**什么 —— 爆炸半径，以及预防/检测/恢复被压成一列。它是对那个格式的批判。

这个 lab 拿同一次压缩，然后**给它定价**。它是那份把*矩阵用一列容纳了两种不同主张*变成*而这个差别
这个月花了你多少小时*的算术。前者是你为什么该停止使用那个格式；这个是该往那个格子里填什么。

## 跑它

```bash
python3 the-stack/labs/07-detection-is-a-window/exposure_drill.py
```

exit code `0` 表示关于这个教训的每一条断言都成立。

## 你会看到什么

1. **四个普通的错误，用三种方式定价。** 一个公开可读的备份 bucket、一个对全世界开放的管理端口、
   一个从恢复里带出来的未加密卷、一把提交进仓库的 API key。都不奇异 —— 每一个都是一个称职的人在
   某个周二会做的事。

2. **扫得更快是一次真实的胜利，而它有一个跨不过去的地板。** 每天 → 每小时，一个月省下 69 小时，
   而仍然剩下 220 小时，**因为一次扫描是在事后跑的。** 一个快 24 倍的扫描器到不了零，而且没有任何
   扫描器到得了。

3. **那条护栏把两个类别带到零，而对另外两个什么都不做。** 一条策略是一份具名类别的清单；你没想到
   的一切仍然在检测那条路径上，而不管怎样那张矩阵在那一行都记着*已预防*。

   **然后再读一遍那些总数，因为护栏那一列比每小时那一列更差。** 部署了 policy-as-code 然后放松扫描
   节奏，整体上*亏了*时间：预防退役掉了两个类别，而另外两个失去了它们的快速检测。**一条护栏退役的
   是一个类别，不是一个扫描器。** 这两者不是替代关系，而那个矩阵格式说它们是。

4. **那条暴露不会在你修好它时结束的发现。** 那把 API key 被提交、在一小时内被注意到，而那次提交在
   80 分钟后被移除。工单上写着 1.3 小时。暴露是 216 小时**而且还在继续**，因为移除一次提交并不能
   让一把 key 变成"没被读过"。修复耗时在这里是一个如实的数字，而它测量的是错误的事件；要紧的那个
   数字是**轮换耗时**，而没有任何扫描器会报告它，因为轮换发生在一个扫描器看不见的系统里。

5. **有了这个单位之后该汇报什么。** 不是*"4 条发现，全部已修复，平均修复时间 41 分钟。"* 而是
   *"这个月 220 小时的暴露；两个类别已被预防、代价为零；两个是只能靠检测的；而这四条里有一条是一把
   凭据，它的暴露还没结束，因为它还没被轮换。"*

## 验证（别光信这个脚本说的）

```bash
python3 exposure_drill.py --break-it fixing-ends-exposure     # exit 1
python3 exposure_drill.py --break-it policy-covers-everything # exit 1
```

`fixing-ends-exposure` 把那把凭据当成那个 bucket 来对待 —— 也就是每一个发现面板里每一个*已修复*
状态背后的那个假设 —— 而恰好只有一条断言挂掉，也就是那条说"一把泄露的 key 是另一种发现"的断言。

`policy-covers-everything` 给那条护栏一份无限长的清单。三条断言挂掉，而第二条是有意思的那条：在
完全覆盖之下那个节奏权衡消失了，所以*那个权衡之所以存在，只是因为一条策略是有限的。* 如果你对
policy-as-code 的模型里没有任何未覆盖的类别，那你建模的就不是 policy-as-code。

想再往前一步，把扫描间隔设成 5 分钟，看着前三条发现朝零收缩、而第四条一动不动。一个扫描器能买给
你的一切，到那时它都已经买完了 —— 而这一页上最大的那个数字，仍然是它碰不到的那一个。

## 重点

**"我们逮住它了"是一句关于一个窗口的陈述。**

三件要带走的事：

- **汇报暴露分钟数，不是发现计数。** 一个活了四分钟的错误和一个活了四周的错误，计数是一样的。
- **一条护栏退役的是一个类别；它不退役那个扫描器。** 如果部署策略成了扫描节奏放松的理由，那这片
  估算面倒退了，而那张矩阵记着一次改进。
- **一把泄露凭据的时钟不会在修复处停下。** 对那一个类别，可汇报的数字是轮换耗时，而它被测量在一个
  没有人把它接到发现面板上的系统里。
